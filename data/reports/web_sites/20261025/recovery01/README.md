# EXP38 recovery01 · 94%에서 멈추던 자료 전달 복구

실제 사용자 오류는 원래42조각 중 `pck-005.gz` 요청의 HTTP500이다. 같은 파일의 서비스 읽기도40.115초에 시간 초과됐다. 근본 저장/edge 원인은 미확정이다. [사건](incident.json)과 [원래 파일 응답](old_asset_http.json)을 보존한다.

게임의 WASM/PCK 전체 바이트를 바꾸지 않고1MiB332조각으로 재분할했다. 새 파일명에는 내용 해시가 포함되어 기존 대형 경로를 재사용하지 않는다. 전송141,196,835B이며 가장 큰 압축 파일1,048,914B다. [재분할 기록](rechunk.json)과 이전 manifest를 보존한다. 기존 게임 export를 다시 실행한 것은 아니다.

실제 loader는 각 조각의 응답/본문 무진행30초를 감시하고 최대3번(1초/2초 간격) 시도한다. 실패한 부분의 전송량만 되돌리고 현재 로딩에서 이미 검증한 조각을 유지한다. 이 상태는 메모리 안에 있으므로 새로고침 후 이어받기를 뜻하지 않는다. 헤더·본문·취소가 영원히 끝나지 않아도 무한 대기하지 않으며, 인증 HTML과 서버500을 구분한다. 크기·SHA 및 실제 EXPLORATION_READY 조건은 유지한다.

- [고장 주입 검사](fault_tests.log): 실제 배포 JS·real gzip/WebStreams/SHA에 제어 시계를 적용한13/13 PASS. WebGL/운영 접속 수용을 대신하지 않는다.
- [실제 로컬 브라우저](artifact_and_browser_check.json): 특정 새 파일에500을 한 번 주입했다. 해당 부분 재시도 안내→332/332→전체 SHA→실제 도시 EXPLORATION_READY를 관찰했다. [화면](local_retry_ready.jpg)·[실제 엔진 로그](local_runtime_dom.txt)·[주입500과 뒤200](local_injected_fault_server.log)을 보존한다. 로컬 실패 주입이며 운영 화면은 아니다.
- [게시 성공](deployment.json): 같은 소유자 전용 Site, 소스 `1544b958b97c0fe009adf8a5e52c3658c6ae69fa`를 게시했다. URL과 공개 범위는 그대로다.
- [실제 배포 자원](deployed_asset_check.json):104.946초에 배포 loader/manifest 동일·332조각 HTTP200·압축/해제 크기·개별 SHA·재조립한 전체 WASM/PCK SHA를 확인했다. 1조각은 두 번째 요청에서 성공했다. 기존 Sites 서비스 자격 증명을 메모리에서만 사용했다. 새 토큰 생성·회전·접근 범위 변경은 하지 않았다.

자동 브라우저는 로그인 게이트여서 인증 후 운영 게임 시작·지속 조작·청취·저장 재접속은 별도 미확인이다. 기존 Mac 게임과 native 설정/게임 자산은 수정하지 않았다. `tools/rechunk_web_site.py`와 업데이트한 `tools/build_web_site.py`가 현재 재현 경로다. 원래42조각의 역사적 검증 숫자를 새332조각 검증으로 고쳐 쓰지 않는다.

다른 사용자 초대·공개 설정은 지원하지만 이번에는 설정을 바꾸지 않았다. 현재 각 브라우저의 단일 플레이이며 공유 세계 멀티플레이나 최대 동시접속 수는 구현/검증하지 않았다.
