# EXP33 — 직접 만든 인물과 실제 사건 대응

2026-10-24 사용자 피드백: 기존 외부 인물의 외형과 팔만 움직이는 타격을 수용하지 않았으며, 직접 만든 캐릭터와 폭행 신고 후 실제 경찰 출동·60초 추격을 요청했다. EXP32의 수치 검사 통과는 이 시각 품질이나 지도 외곽에서의 출동 성공을 입증하지 못했다.

## 자체 제작 범위

`tools/authored_character/build_seoul_resident.py`가 수치로 작성한 해부 단면·연결 곡면·얼굴·머리·의복·손발·UV·텍스처·스켈레톤·가중치를 남녀 기본형×기본/통통/근육×사복/수영복의12개 GLB로 만든다. `game/assets/original/seoul_resident/AUTHORED_MANIFEST.json`에 생성 파일 해시와 손 관절 좌표계를 기록한다. 외부 인체·얼굴·의복·스캔·애니메이션을 읽거나 변환하지 않는다. 남녀 사복과 수영복이 같은 자체 몸/머리/본 계층을 사용하므로 이전 두 공급자 몸/머리의 접합 보정도 실행하지 않는다.

표시 모델 ID는 `SeoulResident_M01`/`SeoulResident_F01`이다. 과거 `Male_Adult_04`/`Female_Adult_07` 선택값은 저장·시험 호환 입력으로만 해석하며 실제 표시 출처를 옛 공급자로 기록하지 않는다. 원래1.70m 플레이어 캡슐·원본 도시 위치/축척·인물/차량 개체를 유지한다. 숨긴 기존 접촉 관절은 시설·차량 API의 기준이며 캐릭터 외형으로 세지 않는다.

## 타격과 피격

F의 왼 잽·오른 스트레이트·왼 훅과 X 양손 밀기는 준비→접촉→회복의 전신 자세를 사용한다. 손가락을 굽히고, 엄지를 주먹 바깥에 접고, 손목과 팔꿈치·가슴/골반·발의 방향을 함께 계산한다. 몸의 체중 이동은 표시 자세에 한정하며 플레이어 물리 원점을 밀거나 카메라 진동을 추가하지 않는다. G는 얼굴 앞 방어 자세이며 체포 방지나 무적 기능은 아니다.

판정은 예전 중심1.9m 원뿔 대신 실제 native 손 접촉점의 직전→현재 구간과 성인 상체 부피·높이·벽 시선을 검사한다. 원래 개는 대상에서 제외한다. 명중한 성인 캡슐에는 짧은 충돌 검사 기반 뒤로 물러서기를 적용한다. 잠깐 반응 소유자가 원래 경로 제어기의 덮어쓰기를 막고, 끝나면 같은 개체·경로로 복귀한다. 체포/탑승/시설 전환 때 지난 타격과 표시 보간 상태도 정리한다.

## 경찰이 오지 않던 원인과 변경

이전4개 초소로는 지도 외곽의 원래 주민 상당수가 경찰에서 수백m 떨어졌고,48m 경로 창의 가장 가까운 목표가 실제 연결된 점인지 확인하지 않았다. 이전 체포 검사는 시험 플레이어를 경찰 옆에 놓았으므로 사건 현장 출동 검사가 아니었다.

새 초기 권역 초소는 원래 보행 인물·대여·정문·사유지·native 지지를 보존하는 별도 경찰이다. 신고 때 경찰을 사건 옆에 새로 만들거나 순간이동시키지 않는다. 가까운 대응 인원이 실제 캡슐·경로로 접근하고, 나머지는 초소/복귀 상태를 유지한다. 연결 가능한 경로 목표를 사용하고 거리·진행·도착 시간을 보고서에 남긴다.

실제 명중 신고마다60초 게임 시계를 시작/갱신한다. 메뉴에서는 정지하며, 잡지 못하고60초를 넘기면 추격을 포기하고 원래 초소로 복귀한다. 체포는 기존 가까운 지상 거리·시선·탈것 소유권을 따르고 조사/유치 후 제어를 복원한다. HUD의 남은 시간과 대응 경찰 거리는 게임 상태이며 실제 경찰 운영을 복원한 정보는 아니다.

## 수영 준비와 커스터마이징 추가 요청

같은 작업 도중 사용자가 이전의 필수 탈의·샤워 절차를 선택 효과로 바꾸고 캐릭터 외형 선택도 요청했다. 수영은 사복/미샤워 상태에서도 기본3.0m/s로 허용하며, 수영복 +15%와 샤워 완료 후90게임초 +10%를 함께 최대25%로 적용한다. 샤워는 기존 청결 수치도20 회복하되100을 넘기지 않는다. 재샤워는 남은 시간을90초로 갱신하며 누적 배율을 만들지 않는다. 메뉴에서는 효과 시간이 멈추고, 풀을 떠나면 일시 수영 속도 효과와 임시 수영복을 정리한다. 회복한 청결은 기존 세션 기록으로 유지한다. 실제 속도는 원래 물리 이동기가 같은 배율을 읽으며 HUD만 바뀌는 효과가 아니다.

외형 선택은 기존 자체 원본을 사용하는 플레이어의 선택 기능이다. 원래 인물·차량 정체성이나1.70m 충돌체/도시 축척을 변경하지 않는다. 선택 항목·저장·상점/수영복 복귀는 최종 실행 기록을 따른다.

실제 일반 OS 조작에서 기존 OptionButton 목록을 열면 embedded window focus 경로의 엔진 종료가 재현됐다. 자동 fixture의 선택 신호 검사로는 발견하지 못한 오류다. 꾸미기7항목을 같은 패널 안의 좌우 버튼과 방향키로 바꾸고, 편집 때만 켜지는 중립 조명으로 해질녘 가시성도 보완했다. 얼굴/피부의 조형을 개선한 것으로 세지 않는다. 원시 종료 로그·메모리 후보·새 UI 검사/일반 OS 확인을 구분해 보존한다.

## 후속 체형·현실감 요청

사용자는 단순한 기본 체형/색상 선택보다 현실감 있는 통통한 체형·근육 체형과 세부 표현을 요청했다. 기본/통통/근육의 독립된 몸·의복·수영복 형태를 남녀 기본형에 연결하고 실제 정면/측면의 배·허리·엉덩이·어깨·팔·다리 단면과 동작 변형을 비교한다. 1.70m는 기존 게임 보행/접촉 기준이며 한국 성별 평균 키를 복원했다는 뜻이 아니다.

참조는 국가기술표준원의 [2022년 제8차 인체치수조사 결과 발표](https://www.kats.go.kr/content.do?cid=23007&cmsid=240&mode=view&page=46&searchField=title&x=14&y=17)의 머리/키 비율처럼 공개된 비례 맥락을 확인하는 수준이다. 전체 사이즈코리아 DB·스캔·상업 게임 인체를 다운로드하거나 변환하지 않는다. 각 체형의 구체 치수는 게임 생성 코드가 작성한 값이며 BMI/건강 상태나 통계적 인구 분포로 표시하지 않는다. 최종 채택 치수와 원본은 제작 manifest를 따른다.

새 체형이 기본 캡슐보다 과도하게 돌출하는지 실제 피부 단면을 대조하고, 걷기/달리기/타격/활동/수영복의 실제 indexed geometry와 원래52본·1.70m·native contact를 검사한다. 체형 수나 검사 개수만 늘어난 것을 현실적인 미술 품질로 수용하지 않는다.

## 부피 확대에서 인체 표면 구조로 수정

사용자의 “덩치만 커지면 자연스러운가, 실제 인체처럼 되어야 한다”는 지적에 따라 앞선 체형 부피 후보는 미술 완료로 채택하지 않았다. `anatomical_surface_fields.py`의 연속 좌표 변형이 갈비뼈를 감싸는 흉곽과 골반의 서로 다른 기울기, 쇄골·견갑·삼각근에서 상완/전완으로 이어지는 방향, 복사근·장골능·둔근에서 대퇴/무릎/종아리로 이어지는 형태를 구성한다. 근육형은 부착 방향을 드러내고 통통형은 하복부·옆구리·뒤 골반·상완 등에 지방을 나누며 뼈의 도드라짐을 줄인다. 전체 메시를 한 비율로 키우지 않는다.

일반적인 위치 관계는 OpenStax의 [골반과 다리의 근육](https://openstax.org/books/anatomy-and-physiology/pages/11-6-appendicular-muscles-of-the-pelvic-girdle-and-lower-limbs), [복벽과 흉곽](https://openstax.org/books/anatomy-and-physiology/pages/11-4-axial-muscles-of-the-abdominal-wall-and-thorax), [골반 구조](https://openstax.org/books/anatomy-and-physiology-2e/pages/8-3-the-pelvic-girdle-and-pelvis)를 참고했다. 그림·메시·스캔·측정 DB를 복사하거나 모델 입력으로 사용하지 않았다. 치수는 프로젝트의 게임 미술 값이며 의학적으로 검증된 해부 모형이나 실측 인체라는 의미가 아니다.

피부와 옷에 같은 연속 변형을 적용해 경계가 따로 움직이지 않게 한다. 손·발의 기존 접촉점과 골격은 보존하며, 수영복에서 노출되는 몸 표면의 샘플 간격은 10mm다. 얼굴의 눈꺼풀/입술과 손바닥/손가락 연결도 별도로 다듬는다. 앞·뒤·측면의 실제 수영복 화면과 움직임을 보고 채택하며, 변형 검사 통과만으로 인체가 자연스럽다고 판단하지 않는다.

피부·손·눈·머리·옷은 [자체 재질 helper](../game/scripts/player/human_skin_materials.gd)에서 반사와 거칠기를 구분한다. 피부/천/머리의 공유 절차 질감은 한 번 만들고 재사용하며, 색상 설정·알베도·불투명도·cull 정책은 바꾸지 않는다. 눈은 머리와 별도 표면으로 분리해 머리색 변경의 영향을 받지 않는다. Forward+에서는 약한 피부 산란을 사용한다. 같은 형상·카메라·조명의 전/후 얼굴 비교를 보존했으며 이 재질 변경을 인체 형상 완성이나 실사 피부로 설명하지 않는다.

초기 수영복 후보에서 보이던 손목/발목의 가로 단차는 몸과 독립 손발 표면의 막힌 cap·다른 단면/normal이 겹친 결과였다. 후속 생성기는 몸을 실제 경계 plane에서 열고 그 loop의 위치·가중치·normal을 손발 bridge와 맞춘다. 발바닥과 손끝 접촉 좌표는 유지한다. 피부 단면의 선형 보간에서 생기던 가로 기울기 단절에는 앵커를 그대로 지나고 구간값을 넘지 않는 C1 보간을 사용하며, 신발 밑창/의복 끝의 의도한 모서리는 구분한다. 검수용 정적 preview의 후면 fill은 뒤쪽 형태 판독을 위한 조명이며 게임의 야간 조명 변경으로 설명하지 않는다.

엄지 기저는 손바닥 외피에 opening을 내고 원래 엄지 proximal까지 web 표면을 연결한다. 눈·안와·눈꺼풀·눈썹은 함께20mm 높이고 눈 열림/홍채·동공을 구분했다. 이 수치는 프로젝트의 미술 조정이며 인구 평균이 아니다. 측면에서 눈이 떠 보이던 고정 Z 배치를 제거하고 각 점의 실제 얼굴 곡면을 기준으로 배치한다. 여성 수영복은 같은 몸 표면에서 잘린 끈없는 디자인으로 바꿔 어깨에서 뜨던 고정 끈을 없앴다. 이 연결 개선을 표정·모발·손끝까지 완성된 사실적 인체로 확대하지 않는다.

수영복 동작에서 보인 큰 어두운 타원을 처음에는 상완이 접힌 결손으로 오판했다. 실제 픽셀 색과 indexed triangle 재질을 대조하니 팔 피부에 수영복 천이 배정된 문제였다. 후보와 보존 원본의 실제 float32 피부+천 삼각형 합집합127,421개·위치별 가중치·rest bone은 동일하다. 의복 후보를 몸통/다리와 팔의 원래 표면 소유 경계로 나눠 여성 수영복3개만 고쳤으며 다른9GLB는 바이트까지 같다. 별도 `check_swim_arm_skin.gd`는 생성기의 표면 분류 계산을 복사하지 않고 실제 arm bone 거리·가중치·indexed material을 읽는다. 보존된 잘못된2GLB는 소재 조건4개에서 실패하고, 고친6수영복은 고정46조건으로 재검사한다. 피부만 남긴 ray 검사는 천 면을 누락하므로 유효한 체적 검사로 채택하지 않았다.

## 검증 경계와 남은 외형 한계

개발 중 원시 실패와 거절 화면을 지우지 않는다. 자체 모델 구조·관절/접촉·보행/시설 회귀는 엔진 검사, 정면/후면/측면·주먹/피격은 실제 native 화면 검토, 일반 기동/OS 입력은 별도 기록이다. 형식적으로 주먹 본이 회전했거나 모든 검사가 통과했다는 이유만으로 자연스러운 외형·타격 품질을 완료로 표시하지 않는다.

현재 최종 판정·선별 실행·일반 기동은 [WORK_STATUS](WORK_STATUS.md)와 [EXP33 집계](../data/reports/authored_character_combat/20261024/summary.json)를 따른다. 이전 공급자 자산과 검사는 과거 재현 자료로 남기며 현재 캐릭터 출처로 사용하지 않는다.

UI 변경 후 현재4실행179개와 실제 일반 OS 선택/취소를 확인했다. 변경 전36실행5560개는 옛 UI 두 파일을 보존한 별도 기능 이력이다. 같은 검사로 실제 popup 생성/초점 경로까지 검증했다고 주장했던 범위를 정정한다. 모델/경찰/수영 생산 소스는 UI 교체 동안 유지했다. 현재 단순한 얼굴·모발과 근접 어깨/팔꿈치·손끝의 외형은 여전히 개선 대상이며, 최신 [매력과 개성의 미술 제안](REFERENCE_DIRECTION.md#2026-10-24-캐릭터-미술-방향--매력과-개성)은 새 얼굴 구현과 구분한다.
