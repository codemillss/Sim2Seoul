# Sol 실행 작업 계획

이 문서는 첫 보행 공간과 사용자 합의 첫 버전을 만들기 위한 **실행 계획**이다. 체크한 항목은 완료 증거가 연결된 작업이며, 체크하지 않은 항목은 완료 판정 전이다. 기존 준비 산출물의 존재·부분 실행 여부는 WORK_STATUS에서 확인한다. 아직 없는 파일 경로는 예정 산출물이다.

기획의 맥락·확정/미정은 [PROJECT_CONTEXT](PROJECT_CONTEXT.md), 전체 순서는 [MASTER_PLAN](MASTER_PLAN.md), 실제 자료 확보 상태는 [WORK_STATUS](WORK_STATUS.md)다. 좌표·속성·충돌·경로 계약은 [TECHNICAL_CONTRACTS](TECHNICAL_CONTRACTS.md), 시험 조건과 판정은 [VALIDATION_PLAN](VALIDATION_PLAN.md)을 따른다. 이 문서의 제안과 계약이 충돌하면 근거를 기록하고 계약을 먼저 정리한다. 미터 좌표로 저장하는 모든 중간 JSON은 CRS·지역 원점·축·단위를 명시하며 WGS84 GeoJSON 검사용 파일과 구분한다. 생성 자산은 `game/assets/generated/`, 수동 모델·장식은 `game/assets/authored/`, 재생성에 보존할 보정은 `data/manual/`에 둔다.

## 실행 방식과 버전 구분

- 기본 실행은 단일 Sol이며 작업 ID 하나를 검증 가능한 단위로 수행한다. 시작 전 선행 작업의 증거와 입력 파일을 확인하고, 끝나면 해당 산출물·검증 결과·미해결 사항을 WORK_STATUS에 기록한다. 기록과 검증 없이 다음 작업으로 넘기지 않는다. 사용자가 여러 작업 또는 전체 구현을 승인한 경우에는 해당 작업 검증 후 선행 조건을 충족하는 다음 작업으로 계속 진행한다. 하위 에이전트는 사용자가 허용했고 이득이 큰 독립 작업에 한해 Sol과 요약 문맥으로 사용한다.
- 작업 종료에는 [EXECUTION_LOG](EXECUTION_LOG.md)의 양식으로 시도·실패·변경·검증·한계를 추가하고 WORK_STATUS의 현재 결과·다음 행동을 갱신한다. 결정/계약이 바뀌면 관련 문서도 함께 갱신하며 산출물과 같은 커밋으로 공유한다.
- 입력 부족이나 실패가 발생하면 그 작업의 대안을 적용한다. 원본이 없는 값을 확정하거나 같은 실패를 계속 반복하지 않는다. 실패 원인과 재개 조건을 기록한다.
- **보행 가능한 중간 버전:** 5단계 완료. 대한문 밖에서 문을 지나 경내의 길·마당·전각 사이를 걷고 서울광장까지 돌아올 수 있으며, 축척·충돌·카메라를 검증한다. 단순 외형을 허용한다.
- **사용자 합의 첫 버전:** 8단계 완료. 장소를 구별할 랜드마크와 정해진 경로의 간단한 보행자·차량을 포함하고, 로컬 패키지와 기기 시험 결과를 남긴다.
- 경내 탐험은 필수다. 개별 전각·일반 건물 실내 진입은 미확정이므로 별도 요구가 정해지기 전에는 구현 범위에 넣지 않는다.
- 낮 고정, 표시 거리, 목표 FPS, 플레이 경계는 검증용 **제안값**이다. 성능 보장이나 사용자 확정사항으로 기록하지 않는다. 날짜별 일정 대신 작업의 통과 조건으로 진행한다.
- 현재 기준 기기는 M1 Pro 16GB다. 추가 M4 Pro는 SSD 1TB이고 RAM은 미확인이다. E01에서 Godot 4.7.2 Standard·Forward+/Metal을 실제 기동 후 고정했다. [환경](environment.md).

### [x] D02 OSM 소구역 원본 추출 — 완료 (2026-10-12)
- 선행: D01.
- 입력: 검증된 한국 PBF 또는 정상 수신된 OSM 원본, 조회 준비 파일.

- 실행: WORK_STATUS에서 이번 추출·감사 결과를 먼저 확인하고, 기존 정상 산출물이 있으면 재추출 없이 그 증거를 검토한다. 미완료이거나 결함을 수정해야 할 때만 기존 조사 bbox(서 126.971, 남 37.5608, 동 126.9815, 북 37.5694)에서 참조 노드·관계가 유지되는 방식으로 추출한다. 경계를 넘는 길·건물과 multipolygon 구성원을 검사한다. 조사 bbox는 플레이 경계가 아니다.
- 완료 기준: 파일 재파싱 성공, 객체 수 기록, 누락 참조·잘린 관계 검사 결과가 있으며 추출 범위가 명시된다.
- 대안: 불완전 관계는 주변 추출 범위를 넓히거나 원본 PBF에서 구성원을 보완한다. Overpass 오류 파일을 정상 원본으로 사용하지 않는다.

### [x] D03 높이·지형·공식 배치 보완 자료 확보 — 완료 (2026-10-12)

## 2단계 — 좌표와 도형 준비

### [x] G01 좌표 변환 기준 확정 — 완료(수평/로컬 좌표 검증, 엔진·현장·실제 지면 검증은 후속)
- 선행: D04.
- 입력: 원본 좌표계, TECHNICAL_CONTRACTS.
- 산출: `config/region.json`, `data/processed/coordinate_reference.json`, `data/reports/coordinate_check.json`.
- 실행: 원본 위경도를 보존한다. 기본안은 EPSG:32652 미터 좌표로 변환한 뒤 지역 원점을 빼고 x=동, y=위, z=남, 1단위=1m로 배치하는 것이다. 원점·축·단위의 정식 값은 `config/region.json`에 고정하고 계약에서 참조한다. 파일마다 원점을 다시 계산하지 않는다. 지면 기준도 계약에 따라 정한다. 국내 SHP는 .prj 확인 후 변환한다.
- 완료 기준: 대표 지점의 역변환·거리·방향 검사가 계약 허용치에 맞고 원점·단위·축이 재현 가능하다.
- 실제 증거: [좌표 검사](../data/reports/coordinate_check.json)의 13개 검사 통과. 7곳의 원본 윤곽 정점, 4쌍 거리, 원점/모서리 역변환, 10m 축을 검증했다. 가공 기준 파일은 `tools/check_coordinates.py`로 재생성하며 공유 보고서에도 동일 기준을 보존한다. [G01 설명](evidence/G01_COORDINATE_CHECK.md). 실제 지면 배정은 G03, Godot 전달은 E04다.
- 대안: 좌표계가 불명확한 원본은 변환에 넣지 않는다. 자료 제공 메타데이터를 확인하거나 해당 자료 사용을 보류한다.

### [x] G02 도형 정리와 원천 연결 — 완료(수평 도형·원천·생성 역할, 높이/실제 메시/현장 검증은 후속)
- 선행: G01.
- 입력: 건물·길·담장 원본과 보완 자료.
- 산출: `data/processed/features.json`(명시한 CRS·축·미터 단위 포함) 또는 미터 좌표 GeoPackage, `data/reports/geometry_check.json`.
- 실행: multipolygon의 외곽·구멍·부속 부분을 처리하고 자기교차·중복·빈 도형을 검사한다. 소스 ID를 보존한다. EPSG:32652와 로컬 원점 좌표는 정식 GeoJSON의 WGS84 좌표처럼 저장하지 않는다. 현재 `osm_preview.geojson`은 WGS84 검사용이며 게임 입력과 구분한다. OSM과 공식 건물을 겹침·주소·명칭으로 비교하며 같은 건물을 두 번 생성하지 않는다.
- 완료 기준: 사용할 도형은 유효하고, 제외/수정 항목마다 사유가 있으며 원천으로 추적할 수 있다.
- 실제 증거: [geometry_check](../data/reports/geometry_check.json) 26개 검사와 [회귀 검사](../data/reports/g02_regression_check.json) 9개 변형 거부. 원본 1,523개·holes 83개 보존, 명시 부모/부분 관계와 보류 사유 기록. [G02 설명](evidence/G02_GEOMETRY_REVIEW.md). 가공물은 공유 도구로 재생성한다.
- 대안: 자동 복구가 외형을 크게 바꾸면 검토 대상으로 분리한다. 핵심 건물은 출처를 남긴 수동 도형으로 대체한다.

### [x] G03 높이와 지면 분류 — 완료(원문·추정·임시 기준 분류, 실제 지형·부분 메시·보행 검증은 후속)
- 선행: G02.
- 입력: 유효 높이·층수·표고 자료, data_gaps.
- 산출: `data/processed/heights.json`, `data/processed/terrain.json`, `data/reports/height_review.md`.
