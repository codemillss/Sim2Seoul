# 덕수궁·시청 첫 버전 제작 계획

계획 기준일: 2026-10-12 · 구현 착수 전 계획 · 다음 실행 모델은 사용자가 선택한 Sol

## 1. 만들 결과

덕수궁과 시청 주변의 실제 도로·건물 배치와 미터 단위 축척을 유지한 개인용 3D 공간을 만든다. 사용자가 3인칭 캐릭터로 대한문 밖에서 경내로 들어가 길과 마당을 걷고, 서울광장과 돌담길을 탐험할 수 있어야 한다. 전통 건축과 현대 빌딩은 단순화하되 장소를 알아볼 수 있는 주요 형태를 표현한다.

이번 요청의 산출물은 **대체 경로에서 확보한 지도 자료와 이 실행 계획**이다. 게임 제작을 완료했다고 보고하지 않는다. 실제 구현은 아래 작업 단위로 이어간다.

## 2. 확정 사항과 구현 제안

| 항목 | 상태 | 내용 |
|---|---|---|
| 장소·축척 | 사용자 확정 | 덕수궁 경내·대한문·돌담길·서울광장·시청 주변, 실제 배치·축척 |
| 표현·조작 | 사용자 확정 | 단순화한 3D, 3인칭, 사람 크기의 임시 캐릭터 |
| 도시 움직임 | 사용자 확정 | 정해진 경로를 움직이는 보행자·차량 |
| 실행·비용 | 사용자 확정 | 개인용 로컬 실행, 무료 도구·공개 데이터 |
| 향후 확장 | 사용자 방향 | 생활·꾸미기·주민 또는 다른 시뮬레이션 |
| 엔진·데이터 도구 | 구현 기본안 | Godot 4 계열 + Python. 첫 기동 검증 후 엔진 버전·렌더러 고정 |
| 좌표 | 구현 기본안 | EPSG:32652 미터 좌표 → 고정 지역 원점. 1단위=1m |
| 첫 조명·시간 | 제안 | 고정된 낮, 날씨·시간 변화는 이후. 사용자 확정처럼 기록하지 않음 |
| 성능 | 제안 | M1 Pro 16GB, 1920×1080, 안정적인 30fps부터. 실측으로 조정 |
| 공간 경계 | 미정 | 조사 상자와 다른 실제 플레이 경계·배경 경계를 지도 검토 후 고정 |
| 전각·일반 건물 실내 | 미정 | 덕수궁 **경내**는 필수. 개별 건물 내부 방·복도는 구현 전 별도 결정 |
| 추가 Mac | 일부 미정 | M4 Pro, SSD 1TB. RAM·OS·실행 결과는 아직 확인하지 않음 |

미정 항목 때문에 자료 검사와 외부 보행 공간 설계를 멈추지 않는다. 실내 범위처럼 구조와 작업량을 크게 바꾸는 항목은 해당 작업 착수 직전에 한 번만 결정한다.

## 3. 완료 지점을 두 개로 나누기

**W0 — 실제로 돌아다니는 중간 버전**

- 실제 원본에서 도로·건물·궁궐 경내 배치를 가져온다.
- 사람 크기의 캐릭터가 3인칭으로 걷고 달린다. 벽·지면 충돌과 카메라 충돌이 동작한다.
- 대한문을 지나 경내의 연결된 길·마당으로 들어갈 수 있다.
- 검증한 동선으로 서울광장·시청 전면·돌담길을 이동한다.
- 실제 데이터를 못 구한 부분은 추정임을 기록하며, 임의의 서울 배치로 대체하지 않는다.
- NPC·차량과 최종 랜드마크 표현이 빠진 W0는 **전체 첫 버전 완료가 아니다**.

**V0 — 합의한 첫 버전**

- W0를 모두 충족한다.
- 대한문·주요 전각·석조전·시청의 특징과 주변 빌딩의 높이감이 드러난다.
- 보행자와 차량이 각각 허용된 경로를 이동한다. 정지·재시작·막힘 처리가 있다.
- 출처·추정 범위, 조작법, 재시작 기능, 품질 설정을 제공한다.
- M1 Pro에서 성능을 측정하고 로컬 실행 파일을 만든다.
- 같은 자료와 버전으로 M4 Pro에서도 실행을 확인한다. 기기 접근이 없으면 그 항목은 미검증으로 남긴다.

NPC 대화·집 꾸미기·실제 교통 수요·멀티플레이·서울 전역은 첫 버전의 필수 작업으로 추가하지 않는다. 개인 건물 실내는 별도 범위 결정에 따른다.

## 4. 단계와 승인 기준

작업의 자세한 입력·출력·절차는 [IMPLEMENTATION_TASKS.md](IMPLEMENTATION_TASKS.md)에 있다. 각 단계는 앞 단계의 완료 증거를 확인한 후 진행한다.

| 단계 | 결과 | 통과 조건 | 실패하면 |
|---|---|---|---|
| 1 · D01–D04 자료 | 원본·출처·재현 가능한 데이터 도구 | 해시/참조 검사, 공식 자료 대조 | 보완 자료 확보. 원본을 가짜 도형으로 바꾸지 않음 |
| 2 · G01–G04 지도 | 미터 좌표 지도·높이 출처·지면·경계 | 위치·축척·겹침·누락·출입로 체크 통과 | 문제만 수동 보정 레이어로 기록 |
| 3 · E01–E04 기동 | 엔진 버전 고정·지도 표시 | 작은 장면과 실제 지도 표시 성공 | 엔진/렌더러/가져오기 문제 분리 |
| 4 · P01–P04 조작 | 사람 크기 캐릭터·3인칭·충돌 | 문 통과, 벽 차단, 지면·카메라 정상 | 전체 장식보다 충돌 문제 먼저 해결 |
| 5 · W01–W04 보행 | 경내·광장·돌담길 연결, W0 | 필수 세 동선 완주, 재생성 후 보정 유지 | 범위/연결 문제를 해결한 뒤 W0 판정 |
| 6 · L01–L04 장소 | 핵심 랜드마크 + 주변 빌딩 | 위치·크기·주요 형태 확인, 추정 표시 | 디테일을 줄이고 비례·실루엣부터 수정 |
| 7 · N01–N04 움직임 | 보행자·차량 경로 | 담장·궁궐/광장 침범 없음, 막힘 회복 | 개체 수·경로 복잡도 감소, 필수 기능 삭제는 아님 |
| 8 · R01–R04 검수 | 기기별 측정·로컬 앱·V0 | 회귀 동선·오프라인·성능·출처 확인 | 병목 조정 후 해당 항목만 재검증 |

의존 흐름: **자료 확보 → 지도 감사 → 공간 계약 고정 → 대한문 작은 구간 → 전체 보행 → 장소 표현·도시 움직임 → 기기 검수**.

작은 독립 장면에서 캐릭터·카메라를 만드는 일은 지도 감사와 병행 가능하다. 전체 지형에 배치하는 것은 좌표·단위 계약이 고정된 뒤 한다. 지도 갱신과 수작업 랜드마크를 분리하면 이후 데이터 교체로 수작업이 사라지는 일을 피할 수 있다.

## 5. 지도 확보와 보완 순서

1. Geofabrik의 날짜 고정 한국 PBF를 한 번 받고, 덕수궁·시청 범위만 로컬 추출한다. Overpass 실패 때마다 같은 조회를 반복하지 않는다.
2. 추출물의 건물·길·담장·문과 이름을 감사한다. 파일을 받았다는 사실과 실제 정확도를 구분한다.
3. 높이·층수 또는 건물 누락이 크면 GIS건물통합정보 서울 SHP를 구해 해당 지역만 대조한다. 필드 정의와 `.prj`를 읽는다.
4. 보도·실폭도로·등고선/표고가 부족하면 국토지리정보원 1:5,000 자료를 확인한다. 다운로드 절차의 Mac 지원·로그인이 막히면 그 항목을 기록하고 독립 작업을 진행한다.
5. Overture는 건물 누락 비교의 예비 경로다. OSM을 원천으로 포함할 수 있으므로 독립적인 측량 검증으로 세지 않는다.
6. 대한문, 담장 개구부, 경내 통행 경로는 현재 공식 관람 안내와 공개 도면을 교차 검토한다. 과거 도면은 현재 모습과 다를 수 있다.

각 경로의 **실제 확보 여부**는 [WORK_STATUS.md](WORK_STATUS.md), URL·권한·접근 조건은 [DATA_SOURCES.md](DATA_SOURCES.md)가 기준이다.

## 6. 첫 실행의 필수 동선

아래는 동선의 목적이다. 좌표·세부 경로는 원본과 접근 정보를 검증한 후 경로 파일에 고정한다.

- **R1 궁궐:** 대한문 앞 → 문 안 → 경내 통행로 → 중화전 앞 마당 → 석조전 앞 접근 가능한 구역 → 대한문. 전각 실내 진입을 뜻하지 않는다.
- **R2 도심:** 대한문 앞 → 확인한 횡단보도/보행 연결 → 서울광장 → 시청 전면. 세종대로를 임의로 뚫어 직선 연결하지 않는다.
- **R3 돌담길:** 대한문 부근 → 공개 통행이 확인된 덕수궁길 구간 → 복귀. 담장 전체 일주를 자동으로 가능한 것으로 가정하지 않는다.

각 동선에 시작 위치·체크포인트·통과 폭·차단해야 할 벽·카메라 문제 위치를 기록한다. 문을 장식용 건물의 충돌체가 다시 막지 않도록 별도 검증한다.

## 7. 일정 대신 작업 크기 관리

아직 실제 데이터 품질과 엔진 기동 결과가 없으므로 고정 완료일이나 작업 시간을 보장하지 않는다. Sol의 **한 작업 단위는 한 목적·한 산출물 묶음·한 검증 결과**로 제한한다.

- 첫 세션: 상태 문서 확인 → 지도 감사 결과 해석 → 가장 큰 결손 3개와 보완 순서 확정.
- 다음 세션: 엔진 기동 또는 좌표·기하 정리 중 선행 조건이 준비된 한 작업.
- 각 세션 종료: 변경 파일, 검증 명령/결과, 남은 결함, 다음 작업 ID만 기록.
- 같은 원인으로 두 번 실패하면 재시도 조건을 바꾼다. 문제 증거와 대안을 남기고 해당 작업에만 집중한다.
- 새로운 기능 요구가 생기면 V0 필수/선택/이후 확장 중 어디에 속하는지 먼저 기록한다.

## 8. 나중 확장을 위해 지금 남길 구조

지도 도형, 시각 자산, 물리 충돌, 이동 경로, 생활 규칙을 서로 분리한다. 건물·문·상점 후보에는 출처를 추적할 안정적인 ID를 둔다. 장식 자산을 교체해도 실제 위치와 출입 연결은 보존한다. 저장 데이터에는 스키마 버전을 둔다.

첫 버전부터 서버·계정·경제 시스템·범용 시뮬레이터를 만들 필요는 없다. 향후 확장 때 건물 ID에 실내 장면/활동/주민을 붙일 수 있을 정도의 경계만 마련한다.
