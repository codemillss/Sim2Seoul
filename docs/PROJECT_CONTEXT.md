# 프로젝트 맥락과 결정

기준일: 2026-10-12. 다른 컴퓨터나 새 에이전트가 같은 목표로 작업하기 위한 결정 요약이다. 현재 진도는 [WORK_STATUS](WORK_STATUS.md), 상세 제작 순서는 [MASTER_PLAN](MASTER_PLAN.md), 변경 과정은 [EXECUTION_LOG](EXECUTION_LOG.md)을 따른다.

## 왜 이 공간을 만드는가

사용자는 실제 서울을 직접 돌아다닐 수 있는 개인용 공간을 먼저 만들고, 그 위에 생활·꾸미기·주민이나 다른 시뮬레이션을 얹고 싶어 한다. 첫 공간은 실제 도로·건물 배치와 축척을 보존해야 한다. 데이터 준비 자체가 최종 결과는 아니다.

장소를 고를 때 유동 인구만이 아니라 다양한 나이·성별의 사람들이 가봤을 법하고 공감할 만한 곳을 원했다. 이어 한국의 전통적인 느낌과 서울의 느낌이 공존하면서 빌딩도 보이면 좋겠다고 했고, **“덕수궁과 시청주변으로 하자”**고 정했다. 따라서 궁궐만 고립해서 만들거나 실제 위치와 무관한 서울풍 배경으로 바꾸면 의도에서 벗어난다.

**“안에도 들어가야지”**라는 요구는 현재 기획에서 대한문을 통과해 덕수궁 경내를 걷는 것으로 반영됐다. 개별 전각·일반 건물의 실내 방과 복도까지 만들지는 아직 정하지 않았다. 이 구분은 이후 범위 논의에서도 유지한다.

## 사용자 방향으로 유지할 사항

아래는 기존 기획에서 합의한 내용을 문장으로 정리한 것이다. 원래 선택지의 A/B/C 문자만으로 다른 의미를 복원하지 않는다.

| 항목 | 유지할 내용 | 판단에 미치는 영향 |
|---|---|---|
| 대상 장소 | 덕수궁 경내·대한문·돌담길·서울광장·시청 주변 | 전통 건축과 현대 빌딩을 함께 경험할 수 있어야 함 |
| 지리와 표현 | 실제 배치·축척, 주요 비례와 형태를 살린 단순화한 3D | 임의 배치로 대체하거나 세부 외형 제작부터 시작하지 않음 |
| 이동 | 사람 크기의 임시 캐릭터, 3인칭 탐험 | 평면 지도 보기만으로 보행 기능을 완료 처리하지 않음 |
| 경내 진입 | 대한문 안쪽의 길·마당·전각 사이를 이동 | 문 개구부와 충돌·연결 동선을 별도 검증 |
| 첫 버전의 움직임 | 정해진 경로의 간단한 보행자·차량 | 도시 분위기 표현이며 실제 교통 예측 모형은 아님 |
| 사용과 확장 | 처음에는 로컬에서 혼자 사용, 이후 생활 요소나 다른 시뮬레이션 | 초기부터 서버·경제·멀티플레이를 필수로 추가하지 않음 |
| 비용과 개발 | 무료 도구·공개 데이터부터, Sol로 개발 지속 | 비싼 모델이나 유료 자료가 필수라고 가정하지 않음 |
| 기기 공유 | 전용 비공개 Git 저장소, 작은 지도와 작업 맥락 공유 | 다른 Mac에서도 동일 입력·계획·증거로 재개 |

## 구현 기본안과 아직 정하지 않은 것

구현 기본안은 개발을 진행하기 위한 선택이며 사용자 확정이나 성능 보장이 아니다. 변경할 때는 이유와 영향, 적용 버전을 기록한다.

| 상태 | 항목 | 현재 내용 / 결정할 시점 |
|---|---|---|
| E01 구현 기준 고정 | 엔진·자료 도구 | Godot 4.7.2 Standard 네이티브 앱 + Python. 현재 M1에서 편집기·세 렌더러 기동을 확인해 Forward+/Metal을 선택. [환경](environment.md)·[기동 증거](../data/reports/engine_startup.md). 템플릿은 R03 전 준비, 도시 성능·M4는 미검증 |
| E02 구현 기준 | 프로젝트·입력·자료 경계 | 정식 `game/`, World/Actors/Presentation과 UI/입력 역할 분리. region은 단일 원천에서 Git 제외 로컬 계약으로 재생성, 실행 중 외부 원본/Python/네트워크 불필요. WASD/방향키·Shift는 입력 의도만 전달, Esc 메뉴는 역할 처리와 입력 차단. [구성/검증](GAME_PROJECT.md). 실제 이동과 서울 표시는 후속 |
| 구현 기준 고정 | 좌표 계약 | G01에서 EPSG:4326 원본 → EPSG:32652 미터 좌표 → 고정 원점, x=격자 동/y=위/z=격자 남, 1단위=1m를 검증해 버전 1로 고정. 수치 변경 없음. [region.json](../config/region.json)·[검증](evidence/G01_COORDINATE_CHECK.md). 실제 지면과 엔진 전달은 후속 검증 |
| 제안 | 조명·성능 | 고정 낮, M1 Pro 16GB에서 1080p·안정적인 30fps부터 검토. 실측 전에는 달성했다고 표현하지 않음 |
| 임시 구현 기준 | 높이·지면 | G03에서 원문/층수 추정/임시값을 분리하고 로컬 지지 평면 y=0을 가정. 실제 해발 기준은 미확정, 132개 수직 예외는 지면 배정 보류. [G03 근거](../data/reports/height_review.md). 실제 지형·통행 허가·플레이 경계가 아님 |
| 후보 작성, 최종 미정 | 실제 플레이 경계·배경 범위 | G04는 필수 원문 동선·궁/광장 참조에 12m 여유를 둔 사유지 제외 검토 도형을 작성. bbox·G03 배경 범위·통행 허가와 구분하며 P/W 검증 후 고정. [G04 근거](../data/reports/movement_review.md) |
| 미정 | 개별 건물 실내 | 방·복도 진입의 대상·수준·작업량은 해당 구현 전 결정. 경내 보행 작업은 계속 진행 |
| 미정 | 점프·최종 캐릭터·낮밤·날씨 | 첫 버전 완료 조건에 자동 추가하지 않음 |
| 일부 미확인 | M4 Pro 환경 | 사용자 제공 M4 Pro, SSD 1TB. RAM·OS 확인과 실제 실행 검증은 남음 |

현재 기기는 직접 확인한 M1 Pro, CPU 8코어/GPU 14코어, RAM 16GB, macOS 27.0이다. 특정 기기의 설치 성공을 다른 기기의 검증 결과로 재사용하지 않는다.

## 사용자 검토 알림

2026-10-13 사용자 지시: 직접 확인·점검·인사이트가 도움이 되는 경우 알려주되 매번 요청하지 않는다. 에이전트가 실행/자료 검증을 수행하고, 사용자 판단이 유용한 배치·축척의 첫 화면(E03/E04), 조작·카메라·동선(P/W), 랜드마크의 장소 인상(L)에는 검토 가능한 결과와 구체적인 관찰 항목을 준비해 알린다. 단순 설치·반복 검사에 별도 방향 승인을 추가하지 않는다. 건물 실내 등의 큰 미정 범위는 구현 직전에 구체화한다.

## 전체 흐름과 완료 의미

**D 자료 → G 좌표·도형 → E 엔진·지도 표시 → P 조작·충돌 → W 보행 → L 장소 표현 → N 도시 움직임 → R 성능·패키지·두 Mac 검수**의 8단계, 32작업으로 진행한다. 세부 선행 조건은 [상세 작업 계획](IMPLEMENTATION_TASKS.md)을 따른다. 작은 독립 장면의 기동 시험 등은 선행 조건이 준비되면 병행할 수 있다.

- **W0:** 실제 배치의 보행 중간 결과. 대한문 밖→경내, 확인한 횡단 연결→서울광장·시청, 확인한 돌담길 구간을 완주하고 축척·캐릭터·카메라·충돌을 검증한다.
- **V0:** W0에 랜드마크 특징·주변 빌딩·보행자·차량·조작 안내·품질 설정·로컬 패키지·기기 검증을 더한 합의 첫 버전이다. W0만으로 V0를 완료 처리하지 않는다.

자료의 참조·도형 검사가 통과해도 실제 서울의 높이·출입 조건·현장 정확도·게임 보행이 검증된 것은 아니다. 원본 값, 추정 값, 수동 보완을 구분한다.

## 결정이 바뀔 때

사용자가 방향을 바꾸면 이 문서의 해당 항목을 갱신하고 실행 이력에 **변경 전후·사용자 지시 또는 구현 근거·영향받는 작업·남은 검증**을 적는다. 좌표나 생성 규칙이 바뀌면 계약·설정·검증도 함께 맞춘다. 이전 결정을 흔적 없이 지우지 않는다.

이 문서는 대화 전체의 복사본이 아니라 이어서 개발하는 데 필요한 합의와 이유다. 확인할 수 없는 과거 발언·날짜·선택지 의미는 추가하지 않는다. 최신 사용자 지시와 문서가 충돌하면 그 지시를 반영하고 영향받는 기록을 함께 갱신한다.
