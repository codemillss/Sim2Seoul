# 서울 생활 시뮬레이션의 참조·구현 방향

작성: **2026-10-22**, 캐릭터 미술 방향 추가 확인: **2026-10-24**. 사용자 방향은 **GTA의 자연스러운 도시 이동과 The Sims의 생활·꾸미기 사이에 있는 서울 생활 시뮬레이션**이다. 사용자가 말한 `rea`는 리버스엔지니어링(RE)을 뜻한다. 이 문서는 참조 방법과 제작 기준이며, 기능 완료와 실제 실행 결과는 [WORK_STATUS](WORK_STATUS.md)를 따른다.

## 경험에서 가져올 기준

## RE의 이번 적용 범위

현재 선택은 **관찰 → 측정 → 기능 사양 → 독립 구현 → 같은 조건의 비교 검증**이다. 공식 기능 설명과 사용자의 조작감 피드백을 먼저 활용한다. 별도 플레이 관찰을 수행할 때도 눈높이, 가속·정지 시간, 회전 반경, 보폭, 시설 이용 전환 같은 기능 사양과 원본 파일·코드·표현의 이용을 구분한다. 참조 영상이나 이미지가 공개돼 있거나 사용자에게 있다는 이유만으로 게임에 포함하거나 AI 도구에 제공하지 않는다.

현재 GTA/The Sims의 특정 게임 바이너리·버전·수락한 이용약관·별도 허가는 제공되지 않았다. 이번 작업에서 원본 게임을 취득·분해하거나 모델·리깅·모션·음향·UI·로고를 추출하지 않았다. 특정 바이너리 분석이나 자산 추출의 허용 여부는 아직 확정하지 않았다.

확인한 약관에는 제한과 예외가 함께 있다.

- [Take-Two 공식 약관 §2](https://www.take2games.com/legal/en-US/) — 페이지 갱신일 2025-02-28. 복제·배포·역분석·파생 작업 등을 제한하며 별도 명시 허가와 적용 법률상 예외를 구분한다. 역분석에는 EU Directive 2009/24 및 기타 적용 법률의 예외가 명시돼 있다. Rockstar의 기존 `/eula` 주소는 현재 [공식 법률 페이지](https://www.rockstargames.com/legal)로 이동한다.
- 같은 약관 §2.3은 콘텐츠를 생성형 AI 도구의 원천 자료 등으로 사용하는 행위도 별도로 제한한다. 2026-10-22 당시에는 GTA 영상·스크린샷·게임 데이터를 자산 생성 입력으로 사용하는 방식을 선택하지 않았다. 2026-10-24 사용자의 명시적 공개 화면 관찰 요청에 따라 브라우저에서 공식 게시 화면을 비교·설명했다. 이 관찰을 이미지 재배포·학습·자산 생성 권한으로 확대하지 않으며, 게임 자산 생성기에 해당 이미지를 넣거나 모델·텍스처를 추출하지 않는다. 이전 외부 인체 교체와 현재 자체 제작은 각각 출처를 구분한다.
- [EA User Agreement §2](https://www.ea.com/legal/user-agreement) — 페이지 갱신일 2026-05-14. 역분석과 소스 코드·데이터 추출 등을 제한하되 EA의 명시 허가 또는 법률상 허용 예외를 둔다.
- [Rockstar 저작물 게시 정책](https://support.rockstargames.com/articles/7bNaeoMFTV0iUDGhStTXvz/policy-on-posting-copyrighted-rockstar-games-material)은 무단 콘텐츠 포팅을 문제 사례로 명시한다. 팬 플레이 영상 게시에 관한 설명을 독립 게임의 자산 재사용 허가로 해석하지 않는다.

따라서 RE 전체를 일괄 불법 또는 일괄 허용으로 판정하지 않는다. 실제 적용 여부는 대상 버전·동의한 약관·작업 방법·허가·적용 법률에 따라 별도로 확인한다. 이 문서는 확인한 조건을 작업에 반영한 기록이며 법률 판단이나 모든 권리에 대한 보증이 아니다.

## 자산을 도입하는 기준

새 자산은 제작자·원본 URL·취득일·정확한 버전과 파일 해시, 라이선스 원문, 변경 내용, 게임 포함·수정·재배포 허용 범위를 함께 기록한다. “무료”·검색 결과·업로더의 설명만으로 이용권을 확정하지 않는다. 자체 제작도 외부 모델·녹음·스캔·모션 사용 여부를 구분한다. 확인한 파일만 도입하고 표시·제공 조건을 실제 배포물에 반영한다.

|---|---|

자료별 실제 포함 파일·공식 사진 참고·자체 생성 음향/텍스처와 세부 고지는 [ATTRIBUTION](ATTRIBUTION.md), 자료 확보 상태는 [DATA_SOURCES](DATA_SOURCES.md)에 보존한다. 데이터 라이선스, 외부 자산 라이선스, 프로젝트 코드의 배포 조건을 하나로 합치지 않는다.

먼저 조형·리토폴로지·표정용 topology/변형을 어떤 제작 방식으로 만들지 결정하고, 현재 단면 조정 방식의 재사용 여부를 검토한다. 그 다음 서로 인상이 다른 남녀 성인 얼굴의 소수 시안을 같은 카메라·중립 표정에서 만든다. 정면/45도/측면과 고정한2~3개 조명으로 비교한다. 그중 얼굴/헤어의 시각 기준을 잡은 뒤 친근한 인상·성숙한 인상·투박한 인상으로 늘린다. 처음부터 프리셋 수나 미남/미녀 슬라이더 수를 늘리지 않는다. 편집 화면의 이름도 외모 점수 대신 윤곽·인상의 설명으로 구분한다. 이는 다음 제작 순서이며 이번12GLB가 그 기준에 도달했다는 뜻이 아니다.

이 관찰에 따른 권장 제작 방식은 **얼굴 전용 조형 → 눈/입을 감싸는 리토폴로지 → 표정 변형 → Godot 실제 조명 검토**다. 현재 단면 기반 몸 생성기는 동작/시설 연결을 확인하는 바탕으로 남기되, 얼굴 디테일은 같은 반경 조절을 반복하는 방식에서 벗어난다. 아직 이 파이프라인으로 제작한 새 얼굴은 없다. 초기 비교 시안은 또렷하고 단정한 인상/부드러운 인상, 후속 확장은 친근한 인상/성숙하고 투박한 인상을 제안한다. ‘예쁨/잘생김’의 단일 정답이나 점수를 정하지 않고 각 인상이 설득력 있게 보이는지를 판단한다.

현재 자체 모델은 기능 연결과 관절/소재 오류를 수정한 **스타일화된 프로토타입**이다. 근접 얼굴의 해부 형태·표정·모발·관절 곡면은 위 기준을 만족하지 못한다. current numerical PASS는 이 미술 격차를 없애지 않는다. 별도 고해상도 조형/retopology와 표정용 얼굴 변형이 필요한지 먼저 검토하고, 같은 단면 반경을 반복 조정하는 방식만으로 완성됐다고 하지 않는다.

원본 게임을 실행/분해하지 않았고 공개 이미지를 저장소에 복제하거나 자체 모델/텍스처/애니메이션 생성 입력으로 사용하지 않았다. 관찰 URL·범위와 판단은 [실제 관찰 기록](../data/reports/authored_character_combat/20261024/character_art_reference_review.json)에 남긴다.
