# 공간·데이터·게임 계약

## EXP27 게임 사건·호출·기상 계약 (2026-10-22)

이 절은 사용자의 자동차 탈취·거리 킥보드 호출·경찰 추격·소방 출동 요청을 반영한다. 원래 AI 자동차를 조작 대상으로 삼지 않던 EXP24의 선택은 이 범위에서 변경하며, 원본 공간과 개체를 보존하는 계약은 유지한다. 최신 실행 판정은 [EXP27 집계](../data/reports/city_sandbox/20261022/summary.json)·[WORK_STATUS](WORK_STATUS.md)를 따른다.

### 같은 자동차의 제어권을 인계한다

- `traffic_car_takeover.gd`는 원래 주행 자동차 14대의 body·Visual·shape·원본 경로 ID를 보관한다. 대체 자동차 생성이나 원래 개체 삭제로 탈취를 구현하지 않는다. 기존 별도 주차 자동차도 유지한다.
- 보행 중 문 옆의 가까운 실제 자동차에 새 물리 E를 누르면, 해당 차가 원래 선형을 따라 감속·정지한 뒤 운전 제어로 넘어간다. 정지 대기부터 같은 상호작용 소유자가 E를 소비하며 상점·건물·다른 탈것의 조작과 겹치지 않는다.
- 확정된 탈취에서만 해당 자동차를 원래 AI 관리자/FIFO 소유권에서 해제하고 신고를 발생시킨다. 취소한 정지 요청은 기존 AI 상태로 돌아가며, 이미 빼앗은 차에 재탑승하는 행동은 새 탈취 신고로 세지 않는다. 내린 차는 같은 개체로 주차·재탑승 가능하다.
- 기존 자동차의 차도 footprint·전체 차체 sweep·바퀴 지지·제동·안전 하차를 그대로 적용한다. 차량 모델 축척이나 원래 충돌 상자를 줄여 공간 문제를 숨기지 않는다.

### Q 호출과 F 입력도 한 번씩 처리한다

- `explore_walk.gd`가 F/Q의 물리 눌림·해제를 보존한다. 짧은 탭은 다음 물리 처리에서 한 번 소비하고, 키 유지/echo·메뉴 중 누른 채 복귀는 새 입력으로 쓰지 않는다. 실내·시설·탑승·조사/유치 중에는 바깥 행동을 예약하지 않는다.
- Q는 원래 대여소 8곳·킥보드 8대를 변경하지 않고 세션 개인 킥보드 한 대만 추가한다. 재호출은 같은 개체를 재사용한다. 현재 지지·근처 전체 차체 지지·공공 원본 면·사유지/정문 보호·native 점유·사이 벽 시선을 모두 통과한 후보에서만 적용한다. 실패하면 기존 상태를 유지한다.
- 성공한 호출은 이전 킥보드 대여 소유권을 정리하고 그 실제 차체를 주차 상태로 남긴다. 새 개인 킥보드는 기존 E 디스패처와 가감속·조향·제동·하차를 그대로 사용한다. 무한 재고 생성이나 공중/실내/사유지 호출은 허용하지 않는다.
- F는 접지 상태에서만 가까운 성인 NPC를 향한 거리·정면 범위·벽 시선을 검사한다. 반려견은 제외하며 0.65초의 입력 간격을 둔다. 짧은 주먹/움찔·문구 반응을 표시하고 명중 시 신고한다. 원래 성인 보행자를 삭제하거나 원래 경로를 바꾸지 않는다.

### 추격·붙잡힘·복귀의 소유권을 지킨다

- 고정 대기·귀가·관찰 위치는 기존 16대의 실제 방향/차체 크기에 맞춘 전방 8m 통로, 표지·거치대와 승하차 공간을 비운다. 복귀가 home 근처에 도달했더라도 실제 캡슐이 이 예약 영역에 남아 있으면 그 자리에서 고정 대기로 전환하지 않는다. 기존 대여소나 충돌을 제거해 새 경찰의 배치 문제를 숨기지 않는다.

새 킥보드 배치도 기존 자전거의 조향/제동 경로를 막을 수 있으므로, 각 서비스의 단독 통과와 별도로 함께 놓인 생산 장면을 재검사한다. 최종 증거 수집 중 입력·공유 기반 제어·모델·대여소 자료를 바꾸면 해당 소스 해시의 실행 결과를 다시 남긴다. 실제 서울의 업체 운영·법규 수용·모든 공간의 주행 허가로 확대하지 않는다.

## 2026-10-20 EXP23 후속 가림·신호 제어 계약

대여소 표지와 실제 자전거는 원본 공공 면/정적 여유 안에 두고, 표시 크기 확대나 가짜 재고로 가림 문제를 숨기지 않는다. 바로가기와 탑승 시점은 일반 카메라를 사용하며 탑승 중 바꾼 pivot을 하차 때 복원한다. 높은 표지 전체 envelope도 native 정적 질의로 검사한다.

횡단 후보는 차량 conflict에 한정하지 않고 기존 source way/node 근거를 보존한다. 명시 무신호·안전한 양쪽 bank 부족·교량 정적 가림은 제외 사유를 남긴다. 실제 판은 자기 crossing의 주기와 같은 재질/숫자를 표시하고 마지막 5초에는 보행 초록을 점멸한다. 신호는 메뉴에서 멈추고 시간대 변경으로 초기화하지 않는다. 기존 conflict의 FIFO/보행 우선권은 별도 권한이며 새 painted stop의 제동 훅이 이를 우회하지 않는다. 녹색/제동 불가능한 황색에 이미 진입한 차체의 뒷부분은 빠져나오도록 자기 경로 station으로 통과를 기록한다. 버스는 원본 도로의 arc 원점과 다르므로 관측 stop 거리+clearance를 자기 station에 더한다. 선택한 근접 신호 접근들에 직교하는 동시 녹색 쌍이 없는지 생성 단계에서 검사한다. 실제 도시 신호 제어의 검증으로 주장하지 않는다.

## EXP23 도로 시설과 작은 버스 서비스 계약

새 거리 시설은 EXP21 `terrain_surface.loaded` 이후에 한 번 생성한다. source 파일·원래 XZ/높이/지면과 건물 충돌체는 수정하지 않는다. 도로 표시는 source drive 삼각형/실제 지면에 투영하며 비충돌 표면으로 만든다. 신호는 현재 교차 conflict의 진입 허가를 추가로 제한하고 기존 보행자 우선·FIFO·교차 중 차량의 빠져나오기를 보존한다. 게임용 주기를 실제 서울의 신호 운영으로 제시하지 않는다. 가로등은 보행/입구 여유와 지지/점유를 검사하고 동시 활성 조명 수를 제한한다.

버스는 기존 source 차도 안의 전체 차체 footprint와 terrain 지지를 검사한 소구간을 물리 이동한다. 문이 닫히고 정차하지 않은 상태에서는 승하차하지 않는다. 승객은 좌석에 붙여 운반하는 게임 표현이며, 원래 플레이어 제어/충돌 상태를 저장하고 검증한 출입 지점에서 복원한다. 새 E는 기존 단일 상호작용 처리에서 소비하며 실내/승강기·시설과 중복 실행하지 않는다. 메뉴·차량 이동 설정은 운행을 정지한다. 다른 장소 바로가기가 성공한 경우에만 탑승 상태를 해제한다. source 데이터·기존14차량/30보행 몸체와 원래 보호 경계는 유지한다.

반려견은 원래 source station/우회와 `move_and_slide`를 유지한다. 다리/발과 머리·목줄은 표시 표현이며 발 디딤 기준은 실제 이동/접지에 맞춘다. 짧은 냄새 맡기/주변 보기 동안 실제 이동을 멈추고 메뉴·기존 보행자 스위치에 따른다. 바로가기 위치는 두 몸체까지 정적 시선과 플레이어/카메라 여유를 검사하며 원래 캐릭터를 숨기거나 벽을 통과시켜 관찰하지 않는다.


자전거는 별도 라이딩 몸체가 실제 `move_and_slide`/전체 탑승 높이 sweep·source 공공 길/차도/사유지·지면 지지를 검사한다. 플레이어의 원래 물리 캡슐/마스크를 유지하고 탑승 중 이동 처리만 대체하며, 다른 운송수단/실내·시설 제어와 동시 탑승하지 않는다. E 하차 요청은 먼저 제동한 뒤 전체 캡슐/지지 검사를 통과한 위치에서만 적용한다. 메뉴/외부 이동의 실패는 탑승 상태를 유지하고 성공한 목적지에서만 복원한다. 두 게임 대여소·재고/반납은 실행 중 체험 상태이며 실제 따릉이 서비스와 연결하지 않는다.

양방향 one-way 원본 면이 겹치는 경우 표시만 공통 중앙 기준의 소유 반면으로 자른다. 중앙선은 한 쌍만 만들고 차선 간격/공백·교차부 표시 제외를 통일한다. 원본 경로나 자동차를 표시 모양에 맞춰 이동시키지 않는다. 보행 신호는 각 road-bank 밖의 지지점에 놓고, 반대편 실제 접근점에서 앞면 법선과 native 시선/지지를 검사한다.

버스의 두 문에 각각 같은 쪽 접근 영역을 두고, 가까운 승객/대기 요청은 열린 문 대기를 유지한다. 문 작동 중 새 E는 현재 정차 버스에만 짧게 예약하며 실제 탑승은 문이 열린 뒤 적용한다. 탑승 의도인 새 E를 이동 중립 latch로 조용히 버리지 않는다. 공중·반대편·벽/닫힌 차체 너머·운행 중 직접 탑승은 거절하고 이유를 안내한다. 버스/자전거에서 내릴 때 새 바깥 캡슐 위치가 native 공간에 게시되기 전에 충돌 예외를 풀지 않는다. 최소2물리 프레임과 실제 차체 query에서 플레이어가 빠져나온 것을 확인한 뒤 쌍의 예외/제어를 복원한다. 검증한 다른 장소 이동은 해당 목적지에 먼저 배치한 뒤 운송 상태만 정리한다.

거리 조작 안내는 실제 패널 높이를 계산해 하단 건물 이름 표시와 겹치지 않게 둔다. 자전거 받침대는 탑승 중 접고 정차/하차 뒤 펴며, 대여소 표지는 고정 판과 양면 글자를 같은 frame에 두어 카메라 회전으로 글자가 판을 뚫지 않게 한다.

### 동일 삼각형으로 조회·표시·충돌을 연결한다

`prepare_runtime_terrain.py`는 공유 높이장/원천 품질 보고서를 만들며 원본 source/world 파일을 덮어쓰지 않는다. `prepare_terrain_surface.py`와 `terrain_mesh_conditioning.py`는 공유 높이장·두 생성기 SHA에 묶인 Git 제외 물리 TIN과 셀별 색인을 준비한다. 출력 체크섬까지 맞는 기존 면만 재사용한다. 다른 Mac의 정상 준비는 `prepare_local_terrain.py`를 통해 공유 준비 보고서를 보존하고 로컬 차이를 Git 제외 기록으로 남기며, 다른 TIN SHA를 자동 수용하지 않는다. 삼각형이 잘못되거나 권역 밖·비유한 좌표이면 지면 API는 결측/거절을 반환하며 최근접 평면으로 메우지 않는다.

`terrain_surface.gd`의 높이/법선 조회와 native 표시·충돌은 같은 실제 삼각형을 참조한다. 평탄 기초 경계는 면의 모서리가 되며, 매우 얇은 면의 수치 횡경사는 공유 모서리의 양쪽 면에 같은 새 참조점을 추가해 보정한다. 원래 꼭짓점을 이동하거나 높이를 제한·면을 삭제해서 해결하지 않는다. 참조 높이를 더 나눠도 개선되지 않는 실제 좁은 건물 틈은 남겨 기록하고 통행 가능으로 간주하지 않는다.

탐험 leaf의 정적 투영은 준비 후 한 번의 동기 처리로 수행하며 혼합 높이 상태에서 물리 프레임을 진행하지 않는다. 원래 데이터의 XZ·1m 축척·원본 면과 건물 자체 높이는 유지한다. 수평 실행 면은 실제 지형 삼각형 경계에서 자르며 **실행Y = 그 XZ의 실제 지형Y + 원래 면의 보간Y**를 사용한다. 수직 면은 XZ 변 길이3m 이하로 나눠 꼭짓점을 지면에 투영하고, 작은 도형/소품은 같은 지면 기준으로 강체 이동한다. 수직 면 전체가 모든 지형 굴곡과 정확히 일치한다고 확대하지 않으며 실제 경계/접촉 검사로 확인한다. 지지체의 위/아래 면을 모두 같은 지형 함수로 투영해 원래 두께와 수직 여유를 보존한다. 건물·전각·문·옥상은 같은 기초 offset으로 강체 이동해 원래 높이/min-height·층수·XZ를 유지한다. 권역 밖 source 면의 실행 사본을 잘라내는 것과 원본 파일을 변경하는 것을 구분한다.

기존 임시 평면과 게임용 미술관3m 언덕은 대체한다. 원래 사유지 보호·산책길 논리 경계는 유지하며 layer32 지형 지지는 NPC/소품에도 남기고 플레이어 자유 탐험 ON/OFF만 해당 mask를 바꾼다. 차량 전용 layer16/mask8 지지도 같은 지형에 연결한다. 배우의 경로 XZ와 거리 기준은 유지하되 접지·차체 경사·교차 사람 감지·수목/소품·스폰/낙하 복귀를 실제 지면 상대 기준으로 바꾼다. 외부 HUD의 `y>6m` 가정은 사용하지 않고 지면 상대 높이/실제 방문 상태를 쓴다.

분리 실내 셀은 자체 좌표를 유지한다. 밖의 문턱/복귀·지붕/물 영역·승강기 목적지만 기초와 지면에 맞춰 재생성한다. 실제 문·기초 높이를 측량했다는 뜻은 아니며 입구 후보 검사와 대표 호텔 왕복을 구분해 수용한다.

### 물리 주기·부하와 현재 step 안전 계약

최신 `explore_walk`만 `@export exploration_physics_hz=30`을 기본으로 삼고30/60Hz를 명시해 실행할 수 있다. 기존 milestone 장면과 프로젝트의 역사적60Hz 검증을 변경하지 않는다. 원인 분리 프로필과 최적화 후에도 전체 배우 물리 step 약19ms가 관측돼60Hz의16.7ms 예산을 넘긴 것이 변경 이유다.30Hz의 step 예산과 렌더 주기는 분리하며, 실제 M1 native 여정/부하 관찰이 수용 근거다. 이것만으로 화면 fps·장시간 성능·M4 통과를 확정하지 않는다.

1m 축척·원본 경로 XZ/거리·충돌 형상, 이동 속도m/s·초 기준 중력/가감속·지연 시간·속도 판정 기준은 그대로다. 테스트 driver와 관측 tick은 실제 Hz에 비례해 같은 시간/속도를 비교한다. 과거60Hz의 tick 수를30Hz의 경과 시간이나 판정 수로 그대로 재사용하지 않는다.

배우의 현재 step 바닥·보호 경계·정적/동적 sweep·상대 인물/플레이어·실제 충돌 이동은 매 물리 step 검사한다. 줄인 것은 미래0.9m **정적** 미리보기의 재검사 빈도로, 정상 구간에서 최대0.15초까지 재사용하고 실패/진행 방향 변경/우회 계획 종료에는 즉시 무효화한다. 현재 step의 실제 물리 결과를 다음 tick으로 캐시하지 않는다. 동일 choose 호출 안에서 물리 상태가 변하지 않는 동일 Vector3 바닥 조회만 재사용한다.

`source_polygon_index.gd`의32m 격자는 원래 private/road 외곽 bbox와 문 point의 후보만 줄인다. 최종 포함은 원래 city의 단일 polygon/holes/엄격 경계 callback, 문은 기존 WORLD XZ의 `(point-door).length()<radius`를 그대로 쓴다. bbox padding을 최종 허용 범위로 더하지 않고 원본 배열을 바꾸지 않는다. 실제 guard가 해당 인덱스를 사용하는지와 원본 격자/꼭짓점·구멍·문 거리 경계±epsilon 동등성을 별도 검사한다.

### 기하 투영 캐시와 인수

`game/data/generated/terrain_projection_cache/`는 Git 제외 재생성 리소스다. 키에는 schema·고정 엔진 버전·기하 종류·노드 경로/실제 변환·전체 물리 지형 SHA·투영·높이 조회 코드 SHA·원래 메시 배열 또는 충돌 도형 속성을 넣는다. 저장한 리소스의 종류·키·형식/표본 수·유한 기하와 통계를 확인하며 없거나 손상·불일치하면 원래 실제 투영 경로를 실행한다. 재질은 캐시에 저장하지 않고 현재 장면의 재질/override를 다시 적용한다.

캐시 적중 시 기하 처리 수는0이며 통계의 면 수는 해당 키의 최초 투영에서 보존한 값이다. 이를 매번 새 면을 처리한 수나 처리 속도 개선의 독립 표본으로 세지 않는다. 최초 계산과 재사용 기동은 따로 기록한다. `check_terrain_projection_cache.gd`의 별도 cold/warm 실제 변환·전체 메시 배열/충돌 형상 지문을 대조하며 MultiMesh의 headless 읽기 한계와 일반 배우 이동은 그 지문 범위 밖이다. 실제 GPU 수목/batch·접지·보행·문/승강기·카메라 수용은 별도 실행과 화면 검토로 확인한다.

최신 공유 파일은 `check_terrain_handoff.py`로 대조한다. `--prepared`는 로컬 생성 입력까지 요구하지만 엔진/새 Mac 수용을 실행하지 않는다. 초기 실패·수정과 EXP20 이전 원시 보고서는 보존하고 현재 소스 해시로 과거 이력을 덮어쓰지 않는다.

거리 장면은 지원 바닥·평탄한 모서리 지지·사유지·기존 보행/차량 선·입구·물체 점유를 확인한다. 피크닉은 낮에만 표시하고 숨길 때 자체 충돌도 끈다. 이정표의 방향/직선거리는 지도 좌표에서 계산하고 보행 경로 거리로 제시하지 않는다. 새 편의점은 지역 원본 POI가 포함된 건물의 외부 edge에 붙이며 기존4record를 유지한다. 실제 입점/정확한 매장 전면/자동 출입을 보증하지 않는다.

버스킹 PCM은 직접 만든20초/mono32kHz/16bit 기타 연주이며 최대32m 거리 감쇠, Esc 음소거, 세계 pause를 따른다. 외부 음원·노래·가사는 반입하지 않는다. [제작 가정](../data/manual/neighborhood_life_design.json),[에스컬레이터/운동](../data/manual/escalator_gym_design.json),[풀](../data/manual/rooftop_design.json) 참조. 이전 EXP14의 ‘오디오 없음’은 당시 상태다.

## 후속 탐험 EXP15 — 보도 경계석과 적당한 산책 인구

`street_curbs.gd`는 현재 game drive 면의 외곽을 따른16구간/약238m의 높이0.12m·폭1.4m 보도 경계 띠다. 원래 차도/보행 지원 Y0를 유지하며 양옆과 끝은 경사로 되돌아온다. 모든 public route·기존 NPC 선·source 보행로의 도로 edge 교차점·명명 횡단3곳·704개 입구 후보/125동·차량 주행 선·source 고체/사유지·미술관 언덕을 보호한다. 런타임 물체와 겹치면 해당 구간만 제외한다. 치수/위치는 게임 창작이고 실측 연석으로 표현하지 않는다.

`street_pedestrians.gd`는 기존 N02와 별도인 물리 사람6명/반려견2마리다. source 보행로를 기준으로 짧고 떨어진 산책 구간을 만들고 한 명은 게임용 언덕 위를 걷는다. layer4의 실제 body·바닥/법선과 캡슐/box sweep, 이웃/사용자 여유·잠깐 정지/재개·막힘 지속 시 방향 전환·끝점 대기를 사용한다. 모든 actor를 기존 traffic human 관측에 등록하고 실제 차량 선에서 떨어진다. 실제 변위로 사람 관절/개의 네 다리를 움직이며 목줄은 주인 손과 목걸이를 잇고 가려짐/길이 한계를 넘으면 숨긴다. 표시 proxy와 카메라는 같은 보간 비율을 쓰며 물리 전에 표시 오프셋을 복원한다. 경로 station은 source XZ 미터로 고정하고 굽은 지점은 연속적인 miter offset, 실제 위치의 역투영은 같은 source 구간 비율로 계산한다. 기존 보행자 이동 체크는 새 산책도 멈추고, 정지 중에도 지면/정지 자세를 유지한다. 메뉴는 모든 산책/동작을 정지한다. 실제 군중·개 행동·목줄 물리나 현장 반려견 접근 규칙은 재현하지 않는다.

재현에 필요한 source hash/치수/보호 범위/한계는 [연석](../game/assets/authored/street_curbs.json)과 [산책](../game/assets/authored/street_pedestrians.json)에 기록한다. 기존 source body·입력/초고속·점프·출입·원래 NPC/차량 제어기는 유지한다.

## 후속 탐험 EXP14 — 거리 상점·생활 장면·게임용 경사

- `street_businesses.gd`는 공식 진주회관 주소/지도와 OSM 스냅샷을 구분한4개 상점 외관을 원본 건물의 바깥 edge에 맞춘다. 진주회관의 공식 지도와 같은 주소 OSM 노드의10.84m 차이, 가까운 보행 가능한 외벽을 쓴 게임 해석을 기록한다. 편의점 현재 입점/정확한 층·점포 단위와 새 실내/자동 출입은 보장하지 않는다. 간판/메뉴·차양·창 안 음식/상품을 native 기하로 만들고 원래 건물 body를 바꾸지 않는다.
- `street_life.gd`의 갓길 차/오토바이·공연/관객·새·가로등은 source 돌담길을 기준으로 한 창작 배치다. 보호된 기존 보행·차량 경로와 입구, 실제 바닥 지지/점유/자체 소품 겹침을 검사하고 실패하면 건너뛴다. 원본 도시 body는 유지하며 주차 차량과 가로등은 별도 소유 충돌체다. 새/사람 동작은 수가 제한된 시각 표현이고 모든 게임용 actor와 시간은 메뉴에서 정지한다. 버스킹 오디오는 추가하지 않는다.

- `museum_approach.gd`는 source `osm:way:183272668:highway_line`의 첫90m XZ를 사용한다. 실제 미술관의 언덕 진입 사실과 게임용 높이 프로필을 구분한다. 중심 보행폭3.2m·흙/잔디 어깨를 포함한7.2m,0→35m에서3m/50m까지 평지/90m에서0m로 돌아와 기존 정문 앞을 유지한다. 지면은 아래까지 닫힌 convex 프리즘이고6×6m/높이3m 전망 쉼터는 별도 지지/가드가 있다. 도시 전체 DTM이나 Copernicus DSM의 지붕 높이를 보행 지면으로 적용하지 않는다.

출처와 창작/한계는 `game/assets/authored/street_businesses.json`, `street_life.json`, `museum_approach.json`에 기록한다. 현재 기능/실행 판정은 [WORK_STATUS](WORK_STATUS.md)를 따른다.

## 후속 탐험 EXP13 — 움직임 안정화

보행/달리기/공중 자세에서 상체 local 위치는 `(0,0.85,0)`, 좌우 roll은0이며 서서히 바뀌는 전방 lean과 팔/다리 동작은 유지한다. 기존 걸음당4회의 상체 높이 진동과 러닝머신 상체 bob을 제거한다. 발은 cosine 앞뒤 경로와 sin² 들기 곡선으로 방향/접지 전환 속도를 연속적으로 만들고 기존 발바닥 높이·IK·주기 제한을 유지한다. 카메라와 캐릭터의 drawable 전용 RenderProxy는 같은 두 물리 시점과 표시 보간 비율을 사용한다. proxy는 물리 처리 전에 원위치로 돌려 관절/시설 검사가 표시 오프셋을 상태로 읽지 않게 한다. Player·Visual·ExplorationAvatar의 위치/회전과 관절 local 값은 물리 소유로 유지한다. 카메라 안정화는 최신 탐험 표시 계층만 대상으로 하며 원본 물리 캡슐·충돌 검사·입력/속도/연속 점프를 바꾸지 않는다. 가림이 생기면 안전한 시점으로 즉시 줄이고 출입/복귀/승강기 전환은 이전 장소와 보간하지 않는다. [제작 가정](../data/manual/stable_motion_design.json)·[현재 검증](WORK_STATUS.md).

상태: 구현 기본안. 사용자 확정 사항과 구분하며, 변경 시 영향받는 작업·검증을 함께 갱신한다. E02 정식 구조·입력/메뉴·로컬 계약, E03 서울 표시·E04 고정 축척, P01 크기·P02 이동/복귀·P03 3인칭 카메라 코드는 독립 시험장에 있다. P04 별도 장면에 도시 정적 충돌은 있고 W01 대한문 연결·W02 경내 순환/앞마당 보행은 있고 전체 동선은 W03–W04다.

D04에서 원천 사용·보류·추정 정책을 [config/data_usage.json](../config/data_usage.json)에 정리했다. 좌표 수치는 기존 `config/region.json`이 기준이며 사용 정책이 좌표 계약을 대체하지 않는다. [data_gaps](data_gaps.md)와 [수동 검토 큐](../data/manual/review_queue.json)는 G02–G04/W 단계의 입력이다.

## 후속 탐험 EXP12 — 연속 점프·옥상 입력·이동 모션

최신 탐험판의 공중 추가 점프 횟수 제한을 해제한다. Space 홀드는 자동 연속 점프가 아니며 새로운 눌림만 받는다. `air_jumps_remaining()`의 무제한 표시는 -1이다. 승강기/메뉴의 기존 이동 중립과 Space 해제 조건을 독립적으로 유지해, 이동키를 계속 누르더라도 새 Space는 받을 수 있게 한다. 시설 사용 중 점프와 메뉴에서의 게임 진행은 막는다.

옥상 진입은 명시적인 `ceiling_unbounded` 전환으로 상공의 인위적인 AABB 상한 복귀만 해제한다. 원본 XZ/난간/건물 충돌·하단 낙하 복귀와 일반 실내의 실제 천장은 유지한다. 상태 전환 실패 시 기존 영역/복귀 상태를 보존한다. 최신 장면의 `Visual/ExplorationAvatar`만 관절형 게임 모델을 추가하며 기존 물리 캡슐은 그대로다. 실제 변위/속도/접지에 따른 걷기·달리기·정지/벽·공중 자세, 초고속에서 제한된 동작 주기와 메뉴/시설 사용 정지를 검사한다. 기존 EXP08의 2회 제한 판정은 당시 버전 기록이다.

## 후속 탐험 EXP11 — 음식·샤워·운동 상호작용

시설 생성에 성공한 실제 설비만 안정적인 ID, 층, room-local use/approach/anchor 좌표로 등록한다. 가까운 동일 층의 지지된 플레이어와 가려지지 않은 설비만 E 대상으로 삼는다. 음식·샤워·러닝머신·덤벨은 별도 상태/소품과 결과 수치를 가진다. 기구 사용 중에도 원본 캡슐/도시 충돌을 유지하며 이동/점프를 중립화한다. 새 E 눌림만 소비해 출입·승강기와 중복 작동하지 않게 한다. 메뉴는 동작/시간/수치/효과를 정지하며 안전 복귀/건물 교체/종료는 상태와 소품을 정리한다. 식사3.6초/3입·입당 포만감8(최대100), 샤워 청결5/초(최대100), 러닝머신6km/h 거리, 덤벨2초당1회는 게임 세션 값이다. 샤워/운동은 새 E로 종료할 때까지 계속하고 실행을 다시 열면 초기화한다. 사람 모델의 팔이 활동 소품을 따르며 중복 손/발 표시와 기본 보행 간섭을 막는다. 실제 섭취·급수/물리 유체·신체 상태를 정밀 재현하지 않는 게임 기능이다. [제작 가정](../data/manual/facility_interactions_design.json)·[동작 제작 가정](../data/manual/exploration_motion_design.json)에 원본/창작을 구분한다. 작은 화면의 상태창은 전체 출처 영역 위에 간격을 두고, E 안내도 그 위에 두며 실제 렌더 뒤 겹침을 검증한다. 최종 검증 범위와 한계는 [검증 계획](VALIDATION_PLAN.md)과 현재 증거에 기록한다.

## 후속 탐험 EXP10 — 시설별 공간과 실제 설비

사용자의 호텔 뷔페·샤워/탕·운동 및 다른 건물의 시설 다양화 요청을 [시설 모듈](../game/scripts/interior_facility_kit.gd)과 기존 detail kit의 층별 프로그램으로 연결한다. [제작 가정](../data/manual/interior_facilities_design.json). 원본125동/1,205층과 부분 평면 치수·층간/계단·승강장/스폰/중앙 통로·외부 충돌은 유지한다.

- 충분한 층수가 있는 호텔은2층 한식 뷔페,4층 피트니스,5층 스파/샤워/탕,6층 연회/비즈니스로 구분하고3층 객실을 보존한다. 일부 프로그램은 위층에서 반복한다. 다른 건물은 식당·강의/운동·세탁/공유주방·어린이/미디어/스터디·작업실/라운지 등 용도별 구획과 설비를 사용한다. 모든 주소가 고유하거나 현실에 해당 시설이 존재한다고 표현하지 않는다.
- 음식은 트레이·국솥·밥/반찬과 주방·식기/젓가락, 운동은 러닝벨트·모니터/손잡이·벤치/덤벨, 샤워는 유리 부스·헤드/배수구·의자, 탕은 타일·림/얕은 물과 열린1.1m 입구다. 기본 시설 입구는1.65m다. EXP10 시점의 장비는 보기용이었다. EXP11에서 먹기·샤워·러닝머신/덤벨 사용을 연결하며, 조리·실내 탕의 목욕 동작은 별도다. 실내 얕은 탕에는 옥상 풀의 부력을 자동 적용하지 않는다.
- 새 solid는 기존 회전 크기 기반 안전 필터와 보호 통로를 통과해야 한다. 장비 생성에 실패하면 부속품만 공중에 남기지 않는다. entry/walk/bounds와 body/Label의 facility_id는 검사 연결 정보이며 실제 형상·지지 검사를 대신하지 않는다. detail/facility 소유 순환은 WeakRef로 끊어 건물을 교체할 때 누적 보유하지 않는다.

### 참조와 제작 해석의 경계

[참조 기록](../data/manual/interior_identity_references.json)은 서울시 공식 사진을 실제 화면으로 관찰한 항목, 공식 안내의 텍스트·대체 텍스트만 읽은 항목, 과거 모습과 현재 명칭을 구분한다. 도서관의 높은 목재 서가·계단식 독서 공간·다색 원형 방석, 신청사의 벽면 녹화·회색 마감과 한국어 안내를 제작에 참고한다. 참조 사진의 픽셀은 다운로드해 게임에 수입하거나 재배포하지 않는다. 사진의 게시일·열람일은 현장 촬영일이나 현재 상태의 실측 증거가 아니다. 2024년 시민청 사진은 과거 참고이며 현재 지하층의 서울갤러리 안내와 구분한다.

### 원본 크기와 층수의 연결

[prepare_building_visits.py](../tools/prepare_building_visits.py)는 기존 G02 `features.json`, G03 `heights.json`, 실행용 `world.json`, W03 `public_walk.json`을 읽어 [source_catalog.json](../game/assets/authored/interiors/source_catalog.json)을 만든다. 입력과 생성기 SHA-256, 원본 ID·외곽 링·구멍·높이 분류·OSM 층수, 제외 이유와 게임 제작 가정을 함께 보존한다. 실행 중 외부 원본이나 Python을 읽지 않으며 [building_visit_catalog.gd](../game/scripts/building_visit_catalog.gd)가 현재 `world.json` 해시를 대조한다. 기존 좌표 설정이나 세계 데이터의 재생성은 이번 코드 변경만으로 필요하지 않다. 세계 원본이 바뀌면 기존 G02/G03 준비 뒤 `.venv-data/bin/python tools/prepare_building_visits.py`로 이 스냅샷도 다시 만든다.

- 원래 635개 건물 중 125개를 게임 방문 대상으로 준비했다. 원본 외곽 안에서 최소 12×16m 바닥을 확보하지 못한 401개, 현재 야외 범위를 벗어난 80개, 역사 건축·문·정자·주차 용도 24개, 기존 사유지 제외 구역과 겹친 5개는 제외했다. 이 수는 카탈로그의 적격 수이며 전 건물의 실제 출입 허가나 모든 방문 동선의 검증 완료를 뜻하지 않는다.
- 바닥은 단일 고정 크기의 방이 아니다. 각 원본 polygon을 0.30m 안쪽으로 줄인 뒤 전체가 포함되는 격자 셀로 직사각형을 찾고, 구멍·오목한 부분을 포함한 원본에 완전히 포함되는지 Shapely로 검사한다. 이것은 원본 외곽 안에 맞춘 **게임 실내 부분 평면**이며, 전체 외곽을 방·복도로 그대로 채운 실제 평면도가 아니다. `rectangle_along/outward`는 바닥의 원본 방향, `along/outward`는 선택한 출입구의 방향으로 구분한다.
- 서울도서관은 약 14.749×57.302m·원문 4층·층간 4.625m, 서울특별시청은 약 47.056×104.894m·원문 12층·층간 3.35m다. 너비/깊이는 선택한 직사각형의 축이며 원본 전체 건물의 외접 너비/깊이와 다르다. 125개 중 78개는 OSM `building:levels`, 47개는 원본 높이를 3.6m로 나눈 내림값을 게임 층수로 사용한다. 최소 층간 3m·최대 60층의 생성 제한을 두며 현재 실제 카탈로그의 최댓값은 28층이다. 층간 높이×층수가 원본 수직 외곽을 넘지 않게 한다. 원문 높이 자체의 추정 분류도 유지하며 독립 실측값으로 바꾸지 않는다.

### 필요한 건물 하나의 실내와 수직 이동

[interior_visit.gd](../game/scripts/interior_visit.gd)는 가까워진 방문 대상 하나를 선택하고 [building_interior_space.gd](../game/scripts/building_interior_space.gd)로 별도 원점 `(650,-100,0)`에 해당 크기·층수의 공간을 준비한다. 한 번에 한 건물의 실내만 유지하며 새 충돌을 등록한 뒤 3 physics tick을 기다려 진입한다. 생성 직후 누른 E는 이 짧은 준비에 한해 연결하며, 문 밖에서 거절된 입력을 나중에 자동 진입으로 예약하지 않는다. 숨긴 이전 방의 충돌을 끈 뒤 제거하고, 현재 방의 바닥·벽·천장·가구·난간 충돌은 외부 원본 inventory와 별도로 집계한다.

층 사이에는 U자 두 구간 계단·중간 참·층 바닥의 계단 개구부를 둔다. 계단의 단 디테일 아래에는 실제로 걸을 수 있는 경사 지지면을 두고, 난간·천장·머리 공간을 별도로 검사한다. Space를 반복해서 뛰어야만 올라가는 장식 계단으로 완료 처리하지 않는다. 현재 층에는 단순한 사람 4명이 실내 경로를 걷는다. 이 사람은 충돌 body가 없는 시각 캐릭터이며 기존 야외 보행자 controller나 상호작용·생활 AI의 확대를 뜻하지 않는다.

각 층 승강장 가까이 E를 누르면 현재 건물의 층 선택 화면을 연다. 목적층 바닥·캡슐 공간을 먼저 검사하고, 닫힌 승강기 화면이 외부를 가리는 동안 승객 위치의 수직 이동을 전환 코드가 담당한다. 그동안 일반 플레이어 물리/이동 입력을 잠시 끄고, 도착 지점을 다시 검사해 유효한 승강장에만 제어를 돌려준다. 층 바닥을 통과하는 중간 구간은 물리 승강기 통로를 연속 보행하는 기능이나 이동하는 플랫폼의 충돌 재현이 아니다. 도착이 막히면 출발층 승강장·해당 층 복귀점·다른 층 복귀점을 확인해 안전하게 취소하며, 모든 후보가 막혔으면 승객 제어를 유지하고, 메뉴 중에는 이동을 진행하지 않으며 메뉴의 대한문 복귀는 진행 중인 승차를 먼저 취소한다. 계단으로 정상 접지한 층과 승강기로 도착한 층의 복귀 지점을 갱신해 위층 낙하가 항상 1층으로 되돌아가지 않게 한다.

### 벽 밀착 상태의 E 입력과 안전한 복귀

[free_roam_player.gd](../game/scripts/player/free_roam_player.gd)는 접지 중 새 누름에만 기본 3m 점프를 시작하며 중력 9.8m/s²와 반 물리 step 보정을 사용한다. 누르고 있기·공중 추가 누름으로 반복/이중 점프나 착지 예약을 만들지 않는다. 공중 수평 이동에도 기존 속도·정규화·경계 검사를 적용하고, 메뉴·설정 변경·복귀 뒤 Space를 포함한 중립 입력을 요구한다. 기존 P02 제어기와 `project.godot` 입력은 변경하지 않는다.
- [exploration_camera.gd](../game/scripts/player/exploration_camera.gd)만 카메라 변환을 게시한다. SpringArm 내부 물리 갱신을 끄고 `camera.top_level=true`, 엔진 보간 OFF 상태에서 직접 보간한다. 물리 구 탐색과 시작/끝 겹침 검사로 위치를 정하고, 이전 카메라에서 다음 위치로 가는 경로가 비어 있음을 물리 단계에서 확인한 경우만 렌더 보간한다. 막힌 전환·복귀는 안전 위치로 즉시 전환한다. 좁은 모서리에서 충돌 회피를 위한 거리 축소는 유지한다.
- 최신 카메라는 near0.08m/FOV62°/far1400m, pitch−65~+20°/기본−18°다. 품질을 바꿀 때 상위 설정 적용 뒤 far1400m를 다시 적용한다. 기존 200m 원거리 절단을 늘리는 변경이며 원천 도시 범위를 확대하지 않는다. 플레이어/카메라 mask45/33과 EXP01 바닥 bit32, NPC/차량 지원면은 그대로다. 두 변환의 덧셈이 과거 증상의 원인이었다고 단정하지 않는다.

### 표시 외형과 충돌의 경계

[seoul_identity.gd](../game/scripts/seoul_identity.gd)는 L02/L03 로드 뒤 궁궐 6곳과 시청·도서관·SFC 3곳의 재질/장식을 보완한다. 기와·단청·창호·벽돌·석재·불투명 유리 격자를 절차적으로 표현하며 장식 267개를 6개 표시 메시로 합치고 캐시 재질 16개를 사용한다. 얇은 지붕 17개 surface에만 양면 shader를 적용한다. 닫힌 벽체·유리까지 전역 양면으로 바꾸지 않는다.

덕수궁 담장 3표시에 불규칙 석재와 줄눈·기와 덮개를 적용한다. W01 담장과 `osm:way:381941848:barrier`/`381941854:barrier`의 겹침은 같은 방향 법선(dot≥0.999999), 같은 평면(허용 0.00005m), 실제 삼각형 덮임을 확인한 **표시 면만** 빼거나 자른다. 겹치지 않는 서쪽/문 주변 표시와 모든 body·shape·layer/mask·변환을 유지한다. 덮개는 원래 2m 표시 외곽 안에 둔다. 원본 지도·footprint·높이 분류와 충돌 resource를 수정하거나 새로운 보행용 계단/실내를 만들지 않는다. [물리 객체·shape 전후 동일성](../data/reports/seoul_detail/20261016/identity_probe.json)과 실제 도시 inventory 검사는 별개 증거다.

### 건물 이름과 도로 위 차량

- [building_names.gd](../game/scripts/building_names.gd)는 실행용 원천 metadata에서 이름 있는 건물 149개를 읽는다. 화면 안·카메라 280m 이내의 지붕 이름은 가까운 순 최대 8개만 표시한다. 물리 priority4에서 6tick마다(60Hz에서 10Hz) 카메라 정면 220m/static mask1 ray로 대상을 고르고, 알려진 대한문 조각/덕수궁 담장은 해당 이름에 연결한다. 이름 없는 원천 건물은 그 상태를 표시하며 임의 이름을 만들지 않는다. 정면 대상이 없을 때는 플레이어와 원천 건물 외접 사각형 사이 55m 안의 이름을 `가까운 건물`로 구분한다. HUD 거리와 캡처용 카메라 위치는 같은 값이 아니다.
- [exploration_traffic.gd](../game/scripts/exploration_traffic.gd)는 원래 세종대로 두 선을 유지하고 각 선에 2대씩 더해 총 6대를 둔다. 추가 차는 동일 선의 1/3·2/3 누적거리에서 초기 배치하며 시작점이 횡단 구역 밖임을 확인했다. FIFO 소유자가 route key이므로 복제 경로에 고유 `_stream_1`/`_stream_2` ID를 부여하고 관리자에 등록한다. 초기 배치 이후 이동·사람 우선·관측 불명 정지·끝점의 시야/거리/빈 진입 조건 재배치는 기존 차량 제어기를 따른다. 차체 충돌 4.2×1.8×1.5m/layer8/mask31을 유지하고 세단 몸체·차창·바퀴·등은 표시 자식으로만 추가한다. 실제 교통 관측이나 새 도로/생활 AI를 뜻하지 않는다.

## C01. 단위와 좌표

### 후속 탐험 EXP01의 별도 계약

- 원래 좌표·OSM·W03·N03 자료와 V0 장면을 유지한다. `explore_walk`와 플레이어 하위 스크립트에 새 야외 범위·속도를 적용한다.
- 조사 상자의 투영된 네 모서리 내부인 x[-450,450], z[-460,460]에 게임용 y=0 바닥을 추가한다. 실제 지형/출입 권한을 뜻하지 않는다. 가장자리·사유지에서 중심을 0.4m 이격하고 이동 구간은 0.05m 이하로 검사한다. 기존 건물·담장 충돌을 유지한다.
- 새 바닥 layer bit는 32, mask는 플레이어 bit2다. 플레이어와 카메라 mask에만 32를 추가한다. NPC/차량 mask와 지원면 제외 RID는 유지한다.
- 속도는 1.4/3.5, 2.24/5.6, 2.8/7m/s 중 선택하며 기본은 2.24/5.6이다. 품질 파일과 별도로 schema1/speed_id/free_roam 세 필드를 저장하고 손상 파일은 기본으로 복구한다. 변경 뒤 중립 입력을 요구한다.
- 일반 건물은 원래 메시/높이/충돌 위의 재질 표현이다. 숨겨진 랜드마크와 historic/civic 재질을 제외하고 공유 shader·최대 16개 재질을 사용한다. 실제 창문·입점 정보를 재현했다고 표시하지 않는다.

- 원본 OSM: WGS84, EPSG:4326. GeoJSON 좌표는 `[경도, 위도]` 순서.
- 작업용 수평 좌표: WGS84 / UTM zone 52N, EPSG:32652. `Transformer(..., always_xy=True)`로 축 순서 고정.
- 고정 원점: `config/region.json`의 `origin_lon_lat`. 조사 상자 중심에 둔 기술적 원점이며 대한문 위치나 시작 지점이라는 뜻이 아니다.
- 변환: `east, north = project(lon, lat)`; `world_x=east-origin_east`, `world_z=-(north-origin_north)`, `world_y=local_height_m`.
- 1 Godot 단위=1m. 아트 자산을 가져올 때 루트 전체에 임의 스케일을 곱하지 않는다. glTF의 축 변환은 엔진 가져오기 단계와 중복하지 않는다.
- 국내 SHP: 원본 `.prj`/메타데이터를 확인해 그 좌표계에서 변환한다. 익숙한 EPSG 번호로 추정하지 않는다.
- 높이 기준은 별도다. OSM `height`는 일반적으로 건물 높이이지 해발고도가 아니다. `min_height`, 지면고도, 지붕고도를 섞지 않는다.
- 지형 원본이 없으면 임시 평면을 사용한 구간을 명시한다. 문턱·보도 턱·경사는 수동 보정 또는 지형으로 교체한다. 임시 평면을 서울 지형 재현으로 보고하지 않는다.
- 원점·축·CRS 변경은 전체 데이터 재생성과 이동 경로·수동 보정·저장 위치의 변환을 필요로 한다. 파일마다 중심점을 다시 계산하지 않는다.

G01에서 기존 수치·축을 변경하지 않고 수평 변환과 로컬 단위 계약 버전 1을 고정했다. 재사용 구현은 [coordinate_system.py](../tools/coordinate_system.py), 증거는 [coordinate_check.json](../data/reports/coordinate_check.json)이다. UTM의 east/north는 격자 방향이며 측지 동/북과 자오선 수렴각만큼 차이가 난다. 로컬 방위각은 `atan2(dx, -dz)`로 투영 평면 방위각과 비교하고, 측지 초기 방위각과의 차이는 별도로 기록한다. 이를 맞추려고 월드 전체를 회전하지 않는다.

E04의 대표점은 G01에 저장한 원본 외곽 링의 사전순 첫 정점으로 고정하며 출입구·중심·스폰으로 재해석하지 않는다. 거리는 XZ 직선거리다. 같은 E03 메시·원점·5방향 10m 합성 축·10m 큐브의 실제 global 좌표/변환을 독립 재투영과 대조하고, 고정 map 시점의 정사영 650m 높이/1152×720 논리 화면에서 10m의 픽셀 투영도 검사한다. 허용 오차는 거리 `max(0.05m, 0.1%)`, 절대 위치/기준물 0.05m, 픽셀 투영 0.05px다. 물리 타깃 크기와 논리 화면을 구분한다. [고정 시점 설정](../config/scale_view.json)·[실제 E04 결과/한계](../data/reports/scale_view/README.md). 기존 region·도시 geometry 계약 수치는 변경하지 않았다.

`y=local_height_m`는 지역 수직 좌표 규칙이다. G01 대표점의 y=0과 위쪽 10m는 합성 검사값이며 실제 지면이 아니다. 해발고도 기준은 계속 미확정이다. G03은 로컬 지지 평면 y=0을 임시 기준으로 정하고 전체 보존 도형 외접 범위+10m를 기술적 범위로 기록했다. 계단/교량/터널/0이 아니거나 해석 불가한 layer/지하/물 예외 132개에는 지면 높이를 배정하지 않는다. 평면은 플레이 경계·스폰·통행 허가가 아니며 DSM 표고나 건물 height를 원점의 해발고도로 취급하지 않는다. [규칙](../config/height_rules.json)·[검토](../data/reports/height_review.md).

## C02. 경계의 세 종류

1. `investigation_bbox`: 자료 추출과 주변 비교용. 현재 약 1km급이며 확정 플레이 영역 아님.
2. `playable_boundary`: 실제로 걷는 폴리곤과 경계의 막음 방식. 필수 동선을 포함한 뒤 고정.
3. `background_boundary`: 멀리 보이는 빌딩·지형 범위. 접근 가능성을 의미하지 않음.

G04 `boundary_candidate.json`의 후보는 R1/R2/R3 원문 연결과 참조 윤곽의 합집합+임시 12m 여유에서 영국대사관 경내를 제외한 검토 도형이다. `finalized_playable_boundary=null`, `spawn_point=null`, 접근 권한 없음이다. 경계 안에 차도/건물/정원이 있어도 통행 허가를 의미하지 않는다. 실제 경계 막음·낙하 복귀는 P/W에서 필수 동선을 검증한 뒤 고정한다.

영역을 가로지르는 건물과 관계 도형은 원본 참조를 먼저 완성한다. 단순한 bbox 정점 필터로 도형을 잘라버리지 않는다. 잘라야 한다면 원본 ID와 잘린 경계를 기록한다. 배경 건물은 본래 위치를 유지한다.

## C03. 출처와 재생성

권장 경로(아직 없는 경로는 이후 작업의 산출물):

```text
config/region.json                    # 경계/원점/축/단위
data/raw/                             # 원본, 재작성 금지. 명시한 지역 PBF/보완 소구역만 Git 포함
data/raw/geofabrik/source.json         # 취득 URL/해시/이용조건
data/reports/                         # 작은 감사 결과·출처 증거
data/processed/                       # 재생성 가능한 지도 중간물, Git 제외
data/manual/                          # 검토한 보정, 자동 생성기가 덮어쓰지 않음
tools/                               # 데이터 준비/변환 도구
game/assets/generated/               # 생성 자산
game/assets/authored/                # 수동 모델·장식
game/data/                            # 게임 실행용 작은 manifest/경로/ID
game/scenes/                          # 지면/플레이어/도시/경로 장면
game/scripts/                         # 이동·카메라·상호작용
docs/evidence/                        # 검증 결과·측정표·로그 위치
builds/                              # 로컬 실행 파일, Git 제외
```

원본 manifest: 공급자, URL/요청식, 취득일, 데이터 기준 시각, 라이선스 URL, SHA-256, 크기, CRS, 범위, 변환기 버전. 작은 사본을 `data/reports/source_manifest.json`에 두어 원본을 Git에서 제외해도 출처가 남게 한다.

원본 갱신은 기존 스냅샷 덮어쓰기가 아니라 새 버전으로 수행한다. 생성 자산 manifest에 원본 해시·설정 해시·도구 버전을 기록한다. 자동 생성과 수동 보정을 분리해 두 번 생성해도 같은 ID와 배치가 유지돼야 한다.

E02는 `game/`를 Godot의 프로젝트 경계로 정했다. authored `world_config.tres`는 manifest 경로만 보유하며 `config/region.json`의 좌표 값은 중복 작성하지 않는다. G01 원천 해시를 대조한 뒤 Git 제외 `game/data/generated/region.json` 원본 바이트 사본과 manifest를 생성한다. 런타임은 허용된 `res://` 계약만 읽고 외부 원본/가공물/Python/네트워크를 요구하지 않는다. E02 당시 자산 목록은 비어 있었고, E03은 manifest v2/`E03_display_only`에서 로컬 `world.json` 하나를 체크섬/크기로 연결한다. 28개 필수 원천/정책/근거 해시를 실행 준비 때 대조한다. [실제 경로·입력·처리 역할](GAME_PROJECT.md). 수동 모델은 `game/assets/authored/`, 자동 생성 결과는 별도 경계에서 재생성한다.

## C04. 공간 객체 스키마

정식 중간물은 미터 좌표 계약을 따라야 한다. 현재 `osm_preview.geojson`은 WGS84 **검사용 미리보기**이므로 게임 입력으로 바로 사용하지 않는다.

필수 공통 필드:

| 필드 | 규칙 |
|---|---|
| `feature_id` | 예: `osm:way:12345`. 노드/웨이/릴레이션을 구분. 실제 ID는 원본에서 읽음 |
| `source_refs` | 제공자·원본 ID·스냅샷 해시. 병합 때 기존 출처를 보존 |
| `kind` | building, building_part, road, footpath, barrier, gate, ground, landmark 등 |
| `geometry` | 도형, 원본 CRS 또는 정규화 CRS, 단위, hole을 포함한 링 구조 |
| `quality` | source_geometry / derived / estimated / manually_verified. 위치와 높이를 각각 구분 |
| `access` | 원본 접근 태그와 게임 허용 규칙을 별도 기록 |
| `override_ref` | 수동 보정이 있으면 보정 ID와 사유 |

G02 중간물은 `data/processed/features.json`의 **별도 JSON 형식**이다. 위경도 GeoJSON으로 읽지 않는다. `coordinate_system`에 EPSG:32652·고정 원점·단위를 적고 `geometry`는 `[x,z]` 미터 좌표, `source_geometry`는 원본 `[경도,위도]`와 EPSG:4326을 보존한다. y/지면/건물 높이는 아직 배정하지 않는다. 같은 원천의 선/면 등 여러 표현은 `feature_id=정식 원천 ID:source_kind`로 구분하고 `entity_id`와 직접 원천·노드/관계 참조를 남긴다.

XZ 폴리곤의 외곽은 반시계·구멍은 시계 방향으로 정규화한다. 이는 중간물 링 규칙이며 E03은 시계 방향 앞면/명시 법선과 실제 엔진 배열을, E04는 고정 거리·기준물·투영 비례를 검증했다. 빈/비유효 도형을 조용히 수리하지 않고 작업을 중단하며 원본 오류를 기록한다. 조사 bbox에서 도형을 자르거나 도로폭 버퍼를 만들지 않는다. [생성 규칙](../config/geometry_rules.json)·[G02 증거](../data/reports/geometry_check.json).

G03의 높이 가공물은 `heights.json`이며 G02 feature_id로 연결한다. 실제 필드는 `height_class`, `height_m`, `min_height_m`, `vertical_span_m`, `source_tags`, 원문 파싱 상태, `source_levels`, `assumption_id`, `component_evidence_ids`, `emit_coarse_body`다. 단일 유효 height를 우선하고, 원문이 있지만 다중/해석 불가면 보류한다. height가 없는 부분/지붕은 전체 높이를 임의로 만들지 않는다. 석조전은 명시 부분의 유효 상단 최대값으로 단순 외곽 상한을 도출한다. 랜드마크 임시값·층수 환산·용도 기본값과 계수는 [height_rules.json](../config/height_rules.json)에 구분한다. 원문 height에는 지붕이 포함되며 min_height와의 차이가 수직 길이다. 원문 min_height가 없을 때 하단 오프셋 0은 관측값이 아닌 로컬 기본안이다. 일반 빌딩 높이를 궁궐 전각에 일괄 적용하지 않는다.

`terrain.json`은 객체별 `ground_class`, `ground_y_m`, 예외 사유, `physical_elevation_m=null`, `walkable_permission=null`, `terrain_shape_verified=false`를 기록한다. 지면 기준·높이 유효성·단순 본체 선택은 통행 허가와 별개다. 정관헌 주변 sand 관계는 원본 전체 면·구멍과 로컬 도형을 참조로 보존한다. 원문·현재 G02 검사·정책/큐·G03 규칙·수동 결정·근거 파일·생성 도구 해시가 달라지면 검토 후 재생성한다. 원문 정확도는 별도 검증이며 모든 추정은 가정 ID를 유지한다.

도로 추가 필드: 중심선과 면을 구분, `width_m`, `width_source`, `lanes_raw`, `oneway`, `layer`, `bridge`, `tunnel`, `pedestrian_allowed`. 폭 추정으로 만든 도로 면이 건물·담장을 덮으면 결함 목록에 넣는다. 중심선 버퍼만으로 실제 보도와 차선을 확정하지 않는다.

G04 보행/차량 가공물은 동일 478개 도로선·보행면의 모드별 기록이다. `source_geometry`는 G02 XZ 원문 도형, `candidate_surface_geometry`는 원문 면 또는 명시 폭 버퍼이며 실제 메시가 아니다. `structural_candidate`, `mode_class`, `access_basis`, 폭/가정 ID·원문 방향, 지면/노드 검토 사유를 분리한다. foot은 access를, motorcar는 motor_vehicle/vehicle/access를 우선한다. 조건/제한은 보류하고 보행면·정원·차도 사이에 자동 권한을 주지 않는다. 관계 member way 노드까지 barrier/access를 보존한다. `runtime_permission=null`, `runtime_surface_ready=false`이며 표고/폭/허가의 독립 확인을 뜻하지 않는다. [규칙](../config/movement_rules.json).

선↔선은 원본 공유 노드, 선↔면/면↔면은 실제 원문 도형 접촉을 연결 후보로 기록하며 근접 스냅을 하지 않는다. 2D 접촉 그래프·원본 노드 체크포인트는 상세 경로/차량 제어/통행 검증이 아니다. gate/passsage와 계단·노드 제약을 유지하고 원문 면의 구멍은 채우지 않는다. 건물/담장 겹침·횡단 후보 차량 접촉을 삭제하거나 자동 절단하지 않고 후속 검토 목록으로 넘긴다. R1 경내·R2 북측 지상 횡단·R3 남측 구간의 원천 연결은 [수동 검토](../data/manual/movement_review.json)에 고정했다. 북측 전체 일주·실내·광장 잔디·사유지를 자유 보행으로 확장하지 않는다.

게이트/연결 필드: 벽 ID, 문 위치, 통과 가능 폭, 전후 지면 높이, 근거, 검토 상태. OSM 문 노드 하나가 건물 충돌체에 자동 구멍을 만들어주지는 않는다.

## C05. 도형과 중복

- 닫힌 건물 면, 복합 관계, 내부 구멍을 보존한다. 중정에 바닥/건물 충돌체를 잘못 채우지 않는다.
- 건물 외곽과 `building:part`가 겹쳐도 단순히 중복 삭제하지 않는다. 부모 외곽과 부분별 높이의 역할을 먼저 정한다.
- relation의 외곽 웨이가 다시 독립 건물로 생성되는지 검사한다.
- 유효하지 않은 도형 자동 수리 후에는 면적·부분 수·holes 변화를 기록한다. 큰 변화는 수동 검토, 조용히 삭제 금지.
- 나라 전체 파일에서 뽑았다고 모든 지역 관계가 완전한 것은 아니다. 추출 정책의 한계와 참조 검사 결과를 보존한다.
- 현재 데이터 감사 수량은 **OSM 객체/미리보기 도형 수**이지 현실의 건물 개수나 독립 조사 대비 포괄률이 아니다.

G02의 보수적 생성 역할은 명시 `type=building` 관계의 outline/part를 먼저 연결하며 공간 겹침은 부모 후보로만 기록한다. 부모 외곽과 부분을 동시에 전체 건물 볼륨으로 생성하지 않는다. 기본 몸체 후보에는 primary 외곽만 넣고 `building:part`와 `building=roof`는 역할을 보존한 참조다. G03 이후 실제 부분 표현을 채택할 때 부모 전체 볼륨과 겹치지 않도록 전략을 교체한다. 이 목록은 실제 메시가 아니다.

동일 유형의 도형과 원본 태그(높이 의미 포함)가 모두 같을 때만 별칭으로 묶고 원본 기록은 남긴다. 설명되지 않은 본체 겹침은 양쪽을 기본 몸체 생성에서 보류한다. 겹침 보고 임계값 0.01㎡는 수치적인 검토 기준이지 측량 정확도가 아니다. 같은 원천의 담장 선/면은 선을 기본 표현, 면을 참조로 구분한다. 모든 보류·별칭과 Overture 22개 미승인 후보의 사유는 검사 보고서에 기록한다.

G03은 [잠정 생성 결정](../data/manual/height_review_decisions.json)에 따라 정관헌의 이름 윤곽 `w/381755268`과 상동교회 본체 `w/1128365145`만 단순 본체에 복원했다. 정관헌의 큰 윤곽/sand 구멍과 교회의 52.1m 작은 면은 참조로 보존한다. 좌표 수정·부분 높이 승인·탑의 시작 높이 추정은 하지 않는다. 상세 부분 전략으로 교체할 때 본체 전체 부피와 동시 생성하지 않도록 다시 검사한다.

E03은 G03 본체 635개만 실제 부피로 표시하며 부분/지붕 참조·지면 예외는 그대로 보류한다. G04 면 370개를 별도 보기용 길/도로로 표시하고 `runtime_permission=null`, `runtime_surface_ready=false`, 충돌 없음 상태를 유지한다. 토지 참조 178개를 색으로 표시해도 통행 권한은 주지 않는다. 겹침을 자동 절단하지 않는다. 담장 두께 0.35m, 15–21/35/55mm 표면 분리는 시각 가정이며 측량값/단차가 아니다. [표시 설정](../config/world_display.json)·[E03 증거](../data/reports/world_import.md). `game/resources/world_geometry/`는 기기별 생성 경계이며 Git 제외다.

초기 제안: 키보드 WASD/방향키, 마우스 카메라, Shift 달리기, Esc 마우스 잠금 해제, 재시작 버튼/키. 걷기 1.4m/s, 달리기 3.5m/s, 키 1.7m, 반경 약 0.3m를 임시 기준으로 삼고 계단·문턱과 함께 조정한다. 이 초기 단계에서 점프는 미확정이었다. 후속 EXP02에서 사용자가 높은 점프를 요청하여 최신 탐험 장면에만 위 별도 계약을 적용했다.

P01의 임시 캐릭터는 전체 높이 1.70m·반경 0.30m의 CapsuleShape3D/CapsuleMesh로 고정했다. 루트는 발 위치이며 외형과 충돌체를 별도 자식으로 두고 중심을 y=0.85m에 맞춘다. 모든 부모 scale=1을 유지한다. 독립 시험장은 24×20m 평면(상단 y=0)·3m 벽·빈 폭/높이 1.20×2.20m 시험문·0.15/0.30m 단차·10m/2m 기준물이다. 시험장 시작 `(-2,0.08,2)`는 실제 서울 원점/스폰과 무관하다. 최소 수직 지지 스크립트는 9.8m/s²·물리 delta로 중력만 적용해 `move_and_slide`하며 수평 속도는 0이다. P02 이동/복귀는 이를 상속한 별도 시험장에서 구현했고, P03 3인칭은 이를 상속한 별도 카메라 시험장에서 구현했다. [P01 코드/실제 검증](../data/reports/player_scale.md).

정지 검사는 1초 정착 후 60초·3,600회 전체의 지면 접촉·Y 범위≤1mm·수직 속도≤0.001m/s·XZ 이동≤1mm와 발 접촉 ±2mm를 확인한다. 실제 GPU 벽시계 관측과 headless fixed-fps의 가속 물리 시간을 구분한다. 화면의 “다시 놓기”는 시험장 수동 배치이며 자동 낙하/경계 복귀 완료로 보지 않는다.

`CharacterBody3D.velocity`는 m/s로 관리하고 `_physics_process`에서 이동한다. `move_and_slide`에 쓰는 속도에 delta를 또 곱하지 않는다. 입력 벡터는 대각선에서 정규화한다. 카메라 기준 수평 방향과 중력을 분리한다.

P02는 기존 P01 파일을 보존하고 `movement_test.tscn`/`movement_controller.gd`에서 InputRouter를 연결한다. 걷기1.4m/s·달리기3.5m/s, 중력9.8m/s², 물리60Hz다. 입력은 길이≤1, 카메라 수평 방향은 y를 제거한 뒤 정규화한다. 수직 시점의 수평 방향을 계산할 수 없을 때는 북쪽(-Z)/동쪽(+X)을 시험 기본 방향으로 사용한다. Visual만 초당TAU(360도) 이내로 돌아가고 캡슐 루트는 회전하지 않는다. 정면 표시 구는 장식이며 P01 본체/충돌 크기를 바꾸지 않는다.

거리용80×40m 평면(중심z30, 상단y0)을 추가해10초35m/대각선 이동을 지지한다. 0.15/0.30m 기존 단차에는 x2→3/y0→.15, x4→5/y.15→.30의 폭2m 진입 램프를 추가했다. 별도1:4 경사(x−9→−5/y0→1)와 도착 평면도 합성이다. 자동 계단 오르기·현실 보도턱/경사·서울 지형을 확정하지 않는다. 시험 영역은 main XZ범위(-11.5,-9.5)~(11.5,9.5), 연결(-3.5,9)~(3.5,12), 거리구간(-39.5,10)~(39.5,49.5)의 합집합이며 지도 bbox/플레이 경계와 무관하다.

발y<−3m·시험 영역 이탈·복귀 버튼은 시작(-2,.08,2)/identity 회전으로 복귀한다. 매 복귀 시 아래 ray의 지면 법선/높이 간격(.005~.20m)과 전체 캡슐 겹침0을 확인하고, 지원 없는 스폰은 이동/복귀를 중지한다. 복귀는 위치·Visual 회전·속도를 초기화하고 이동키/Shift가 중립이 될 때까지 수평 입력을 잠근다. 메뉴의 Actor 물리 정지와 복귀/재개 후 키를 계속 누르는 경우의 이동 차단도 확인했다. P03 별도 시험장에서 메뉴 마우스 잠금 해제/복구도 구현했다. [P02 실행/실제 검사](../data/reports/movement.md).

카메라는 SpringArm 계열 충돌 탐색을 사용하되 플레이어 자신은 제외한다. 초기 근접 거리·회전 한계·감도는 설정으로 둔다. 건물 모서리/문 아래/담장/계단에서 카메라가 벽 뒤로 이동하는지 확인한다.

P03 기본안은 `camera_rig.tscn`의 발+1.3m 추적 pivot, perspective FOV65°/near.05m/far200m, 기본 거리4.5m/휠 요청범위2~6m/단계.35m다. 감도.0025rad/화면pixel, pitch−55~+15°/기본−15°, yaw wrap±PI. 화면 크기 보정된 `screen_relative`를 사용한다. 마우스 이벤트는 요청각만 바꾸고 Player 이동 신호에서 위치/각을 적용한다. Player 물리priority0 → SpringArm 내부1 → 최종 카메라 게시2 순서로 이전 tick의 위치/충돌값을 읽지 않게 한다.

SpringArm은 반경.20m 구·mask1·margin.08m와 플레이어 RID 명시 제외를 사용한다. 충돌 시 거리는 즉시 축소하고 확장은 최신 안전 거리 안에서6m/s로 제한한다. 코너의 한 tick 겹침을 실제로 발견해 최종 구 overlap 확인 후14회 이분 탐색/추가5mm 여유로 보완했다. 정상 모든 tick의 카메라/near-corner ray 겹침0을 확인했다. 구의 초기 pivot이 정적 구조 안에 놓인 배치는 검증 대상이 아니며 행렬은 P04에서 확인했고 W01 제한 연결의 지면/스폰·pivot 초기 배치는 별도 증거로 확인했다. 전체 도시 적용과 실제 지형은 후속 검증이다.

1152×720에서 near plane 네 모서리의 중심 거리 약.07818m가.20m 탐색 구에 들어간다. 이 검증은 임의의 극단적 화면 비율 보장이 아니다. 근접 거리<1.5m에서 Visual을 숨기고>1.8m에서 다시 보여 임시 몸체가 화면을 가리는 현상을 줄인다. 근접 상태에서 전신이 항상 보인다는 기준은 아니다. 원래 P01/P02 외형·물리 파일은 유지한다.

P04 원본 자료의 대한문/중화문 본체는 닫힌 상태이며 자동 개구부·통행 권한·경계·스폰을 만들지 않는다. 별도 W01 장면에서 대한문 연결만 열었고 W02는 중화문을 피하는 원문 대체 순환을 사용하며 중화문 충돌을 보존한다. 생성 계획은 world/region/rules/생성기 hash 및 selected/excluded ID를 대조하고 잘못된 자료는 충돌 생성 전에 거부한다. 시험장과 도시 보기 전환 시 비활성 공간의 layer/mask는0으로 하고, 도시 보기에는 플레이어 조작/이동을 연결하지 않는다.

- 플레이어는 지면·벽·건물과 충돌. 보행자와의 반응은 밀침 대신 정지/우회 등 명시한 규칙 사용.
- 카메라 탐색은 정적 장애물을 포함하고 플레이어/장식/필요 없는 NPC는 제외.
- 움직이는 객체에 복잡한 정적 삼각형 충돌체를 그대로 붙이지 않는다.
- 시각 도형과 충돌체는 분리 가능하되, 체감되는 벽 위치·문 폭은 맞춰야 한다.
- 단차는 플레이어 이동 능력에 맞춰 실제 메시/간소화 충돌 램프를 선택하고 보정 사실을 기록.
- NPC/차량의 시각 경로 보간만으로 벽 관통을 막았다고 판정하지 않는다. 경로의 폭과 장애물 여유를 검사한다.
- 차량은 도로 중심선에서 임의로 달리는 대신 확인한 방향·차로 위치의 소수 경로를 사용한다. 보행 구간/궁궐로 진입하지 않는다.
- 처음에는 보행자/차량 경로를 분리하고 교차 구간에서는 간단한 정지 규칙을 사용한다. 검증하지 않은 신호·교통 현실성을 주장하지 않는다.

교통·군중 개체 수는 설정 파일에 둔다. 임시 부하 프로필은 성능 검증 문서가 기준이다. 멀리 있는 개체를 줄이더라도 가까운 개체가 눈앞에서 소멸하지 않도록 재생성 위치를 검토한다.

## W03 보행 경계 Resource와 도심 연결

`W03-play-boundary-v1`은 G04 후보 안에서 원문 보행면·선과 W02 지원면을 결합한 현재 장면의 게임 경계다. 후보 자체나 bbox를 자유 보행 권한으로 승격하지 않는다. 북측 marked/zebra w1230789306과 두 원문 shared-road-node 접속부만 차도 중심선0.5m 제외에서 예외로 둔다. 보행 지정 분리 cycleway의 보행 폭은2.4m 추정으로 따로 기록하며 실차도 경계/현실 신호/통행 허가를 주장하지 않는다. 차량 제어는 후속 N03, 점유된 접속부에서 정지해야 한다.

## L04 결합 화면·보행 재검수

L04는 일반 게임을 바꾸지 않는 검사 전용 장면으로 실행한다. 기존 낮 조명을 이번 비교의 구현 기본안으로 고정하며 낮/밤 시스템을 추가하지 않는다. 이름표를 숨긴 동일 시점의 교체 전/후 3인칭 화면과 지면 위1.6m 관찰 화면을 구분한다. 눈높이 카메라는 검사 전용이며 플레이어의 새 조작 모드가 아니다. 사람 크기1.7m와 실제 카메라 행렬/FOV의 투영 비례도 별도로 대조한다.

관찰 지점은 기존 체크포인트·경로 정점 또는 기존 W03 이동 영역 안의 보조 지점이다. 관찰을 위한 배치는 연속 보행 증거가 아니며 실제 현장 출입 가능성을 추가하지 않는다. 대한문/광장 왕복은 그룹 안에서 배치 없이 검사하고, 그룹 사이 배치와 정지 회전은 별도 표시한다. 돈덕전·정관헌처럼 가린 외형은 부분 노출/인지 미확인을 기록하며 화면을 위해 원본 위치·충돌·통행 범위를 바꾸지 않는다.

전체3.3km 회귀의 재사용은 L03 합격 당시 소스·실행 자산·입력·검사 도구의 정확한 SHA 일치와 원시 관측/판정/요약의 저장 해시 일치에 한정한다. 한 파일이라도 달라지면 이 재사용 경로를 거부하고 영향을 받는 회귀를 다시 실행한다. 새 국소 검사와 과거 전체 여정을 한 번의 새 연속 실행으로 합치지 않는다. 진단용 흑백 마스크의 픽셀 수는 대상 외형의 노출량이며 사람이 장소를 알아본다는 증거가 아니다. [계획 원천](../data/manual/landmark_review_plan.json)과 [최종 검수 보고서](../data/reports/landmark_review.md)에 실제 판정 범위를 남긴다.

## L03 도시 외형·기존 모델 수정

L03은 `city_landmarks.tscn`에서 L02를 상속한다. 시청·도서관·광장·SFC의 원본 표시4개만 교체하고 L02 궁궐·W04 body/지원면/경계·문/경로는 유지한다. 새 충돌/보행 권한은0이다. 모든 표시 삼각형의 전체 XZ 투영은 해당 원본 footprint/구멍 안에 있어야 하며 기존 수직 외곽을 넘지 않는다. 광장은 `top=null`을 무제한 높이로 읽지 않고 기존 Y=0.017 단일 평면으로 유지한다.

시청 곡선은 실제 유리면의 여러 수직 단면·높이별 깊이 변화와 비선형성을 검사한다. 긴 처마/평면 지붕과 곡선 유리를 혼동하지 않는다. 도시 표시18개 부품을7재질로 묶으며 유리는 불투명 색으로 단순화한다. 미터/높이 연결·수작업 곡률/색/간격·공식 자료 차이는 [L03 판단](../data/manual/l03_city_decisions.json)에서 분리한다.

## N02 물리 보행자와 접촉 계약

## N03 실제 차량과 교차·반복 계약

N01 두 편도선/원문 정점·정지/확장 출구와 오른쪽1.6m 오프셋을 그대로 쓴다. 차체4.2×1.8×1.5m·여유1mm·최고5m/s/가속1.5m/s²/제동3m/s²·공중 중력9.8m/s²다. 확장 횡단 구역에서는2m/s로 줄이는 보수적 구현 기본안을 추가했다. 실제 `move_and_slide`의 같은 tick 거리 예산 안에서 선분 정점/방향을 이어가며 일반 이동에서 좌표를 덮어쓰지 않는다. 전체 상자 탐색은 실제 지원면RID만 제외하며 지원면 부재/3mm 초과 경로 이탈 시 기다린다.

물리순서는 사람0·차량1·카메라2다. 매 tick 실제 사람 위치를 먼저 읽고 사람 존재/불명 또는0.1초 초과 관측이면 진입을 막는다. 빈 상태가 연속1초 유지된 뒤 FIFO 한 대만 허가하며 확장 출구를 지난 뒤 해제한다. 차량 이동 스위치가 꺼져도 관측은 계속하고 관측 tick 공백이 생기면 빈 시간을 초기화한다. 구역 내 사람의 갑작스런 출현은2m/s·전체 상자 제동/접촉 시험으로 별도 확인한다. 실제 서울 신호/차선 측량·법규 검증이 아니다.

재배치는 실제 끝점에서 속도0·접지 상태를 확인한 뒤 현재 카메라의6frustum 평면/양 끝 전체8모서리·사람 표면30m·진입 상자 동적점유0·최신 관측이 모두 맞을 때만 허용한다. 교차 관측과 카메라가 갱신된 동일 tick guard를 사용하며 조건 미충족 시 기다린다. `repeat_spatial_edge=null`은 유지하고 숨은 U턴/역주행을 만들지 않는다. 저장된 guard의 직전 실제 위치/속도/접지와 원문 끝점, 실제 재배치 전후 위치를 독립 대조한다.

실제 명령5.0002m/s·float32 위치 차분 속도5.01m/s·tick당5/60m+1mm, 원문/지원/침투5mm·실제 화면 시간2% 상한을 함께 적용한다. 위치 차분 가속/제동은1.53/3.03m/s²를 허용하며 각각 구현1.5/3에 float32 관측0.03을 둔다. 수동 즉시 정지는 일반 주행 제동 수치에 합산하지 않는다. 관측의 모든tick 요약과10Hz 저장 표본, 실제 engine 결함·저장 변조·loader 거부를 구분한다. [실제 결과/실패/한계](../data/reports/vehicles.md).

## N04 연속 도시 검수 계약

N03 일반 게임의 장면·지도·충돌·속도·2NPC/2차량을 바꾸지 않는다. 새 자동 검수기는 W04 원문11단계/334구간의 순서·끝점을 그대로 사용하되 실제 입력으로 각 끝점0.065m 이내에 도착할 때까지 걷는다. 기존 고정시간 직진을 움직이는 NPC 접촉 상황의 완주 판정으로 쓰지 않는다. 측면 양보는 시험 운전용 helper이며 일반 게임에 자동 보행을 추가한 것이 아니다.

양보는 가까운 NPC 앞에서 최대0.85m 측면 후보를 고르고, 기존 movement/support·전체캡슐/정적체적·실제capsule sweep을 통과한 경우만 사용한다. 일반 원문선 오차0.18m, 기록된 양보/복귀 동안만 최대1.05m이며 실제 보행 영역/지지·침투5mm 기준은 유지한다. 원문선0.18m 이내 복귀 후에만 일반 이동 상태로 전환한다. 플레이어 좌표 덮어쓰기나 NPC 이동/제거로 통과시키지 않는다.

## R03 내보낸 앱과 검수 입력 경계

원본 `game/project.godot`의 E02 main과 기존 지도·충돌·이동 코드는 보존한다. 내보내기는 별도 임시 프로젝트에서 `v0_walk.tscn`을 main으로 지정하고, 고정된 지역 실행 번들·품질 설정·출처·Godot/제3자 라이선스·ICU만 복사한다. Python·전국 원본·개발 캐시는 앱 실행에 필요하지 않다. 공식 동일 버전 universal2 macOS 템플릿을 사용하고, 텍스트 `.tres`를 런타임에서 원문 SHA로 읽는 기존 계약 때문에 임시 프로젝트의 `editor/export/convert_text_resources_to_binary=false`를 유지한다. 기존 loader의 원문 검사를 완화하지 않는다.

새 `PackageProbeDispatch` autoload는 내보내기 사본에만 추가한다. 일반 실행에서는 입력·물리를 처리하지 않고 아무 검수기도 실행하지 않는다. `--automatic-probe`와 허용된 `--sim2seoul-test=quality|urban`이 함께 있을 때만 앱에 포함된 두 고정 검수기로 전환한다. 표준 export 템플릿이 무시하는 `--script`를 성공한 실행 수단으로 기록하지 않는다. QA는 실제 release 바이너리/PCK에서 실행하며, 합성 엔진 입력과 OS 입력·사람 조작을 구분한다.

정적 export manifest는 제작 당시 입력/앱/ZIP/서명을 기록한 불변 자료다. 제작 시점의 `runtime_tested=false`나 `roundtrip_verified=false`를 나중에 고쳐 쓰지 않는다. ZIP을 저장소 밖으로 풀어 원래 앱의 파일별 SHA·권한·심볼릭 링크와 대조한 뒤, 네트워크와 저장소 읽기/쓰기를 차단해 실행한 별도 `package_check.json`으로 실제 기동/품질/전체 여정 판정을 보탠다. 완료 후 같은 source·manifest·원 앱·ZIP·추출 앱·서명을 재확인한다. `.app`/ZIP/템플릿은 Git 제외이며 코드·지역 원본·검수 도구·증거와 해시를 함께 공유한다.

최초 V0 HUD는 창 크기를 바꾸기 전에도 실제 minimum 높이로 맞아야 한다. 폭을 먼저 정한 뒤 `minimum_size_changed`에 지연 높이 조정을 연결하며, 전체 메뉴를 매 프레임 다시 배치하지 않는다. standard/no-resize0 최초 프레임과 캡처 전후의 HUD·player 화면 사각형을 따로 관측한다. [발견·수정 전후](../data/reports/r03/development/hud_fix_summary.json).

## R04 패키지 경로와 미접근 기기의 계약

다른 clone에서 원 manifest의 옛 절대경로를 수동 수정하지 않는다. 같은 ZIP·app inventory/PCK·catalog bytes가 맞을 때만 세 경로와 preservation catalog key 두 개의 파생 바인딩을 허용한다. 모든 다른 JSON 값과 key 순서·역적용 원본 복원을 확인하고 원 manifest를 그대로 보존한다. 상대 source SHA와 실제 앱 실행은 기존 package checker에 남긴다. ## EXP22 가로수 세부 외형

원래 식재 JSON의 source ID/XZ·source/게임 보완 구분과 EXP21 지면을 유지한다. 원래5.3~6m `height_m`는 이전 제작 기준이며 새 표시 수고와 분리한다. 새 약10m 안팎의 크기·수형·색은 성목 느낌을 위한 게임 아트이며 실측 수고/수종 동정이 아니다. 줄기 충돌은 반경0.17m·높이3.1m/최대128개 활성 상태를 유지하고 수관/세부 가지·잎은 비충돌이다. 수관 머리 여유는 최소2.65m를 유지한다.

표시 모델은 source 바닥 원점에서 수직 성장하며, per-tree 안정적 회전/높이·폭과 색 변이를 쓴다. 공용 가지/줄기 메시·비정형 잎 무리와 별도 근거리 잎 메시를 공간 MultiMesh로 재사용한다. 근거리 잎은 거리 제한을 두고 원래 지면 지원/문/나무 위치/도로/사유지/배우 컨트롤러를 수정하지 않는다. 바람 변위는 잎의 작은 표시 이동뿐이며 새로운 물리 경계가 아니다.
