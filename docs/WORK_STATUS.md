## D03 보완 자료에서 확인한 점

- Overture 수신 736개 중 외접 상자만 겹친 3개를 제외해 실제 교차 대상 733개를 분리했다. OSM 원천 711개와 비OSM 윤곽 후보 22개다. 실제 누락 건물 22개 확정이나 자동 병합은 아니다.
- 선택 대상의 유효 숫자 높이 100/733개·층수 134/733개. 높이는 모두 OSM 원천이고 독립 높이 보완은 얻지 못했다. 현재 OSM 높이 하나가 Overture에는 없어 전체 교체도 하지 않는다.
- Copernicus DSM 사본 38×32 픽셀, 5,356 bytes. 수평 WGS84·수직 EGM2008, 약 24.54×30.83m 픽셀의 지표값이며 문턱·계단·맨땅 높이로 사용할 수 없다. 실제 표고 기준은 미정이며 G03 로컬 y=0 가정과 구분한다.
- 국내 서울 SHP는 로그인/전송 도구 단계에서 막혀 미수신이다. 공개 컬럼 정의서는 실제 받았지만 현재 서울 파일의 PRJ·높이·층수 실물 값 검증을 대신하지 않는다. NGII 상세 지역 원본도 미수신이다.
- 공식 덕수궁 지도와 접근·공사 안내를 참고로 확인했다. 남측 담장 공사와 10-25~11-19 예정 평성문 통제를 기록했으며 R2 연속 횡단 연결·R3 전체 순환은 미확정이다. crossing 노드 60개는 후보 위치다.
- 현재 보완 검사 17개 통과. 원본 보존, 범위 밖 객체 분리, 미리보기 해시·설정 연결을 검증했다. 실제 경로 완주·측량 정확도·게임 성능 검증은 아니다.
- 국가 지도·전체 DSM 없는 별도 파일 사본에서도 15개 지역 검사와 변경된 미리보기/원본 거부 검사를 통과했다. [재현 확인](../data/reports/d03_portability_check.json). 현재 M1의 기존 도구 환경을 사용했으며 M4 실행은 미검증이다.

## D04 사용 판정

D04는 원천과 부족한 항목의 처리 기준을 정한 작업이다. 단일 높이 원천 후보 100개·층수 추정 후보 53개·두 속성 없는 557개·다중 높이 보류 1개로 분류했고, 원본/미리보기/설정과 집계 검사 6개를 통과했다. D04 당시에는 실제 추정 높이·문 폭·수동 보정 좌표·최종 보행 경로가 없었다. 높이 추정/임시값은 아래 G03에서 만들었으며 문 폭·승인된 보정 좌표·최종 경로는 여전히 없다. 단일 높이 숫자가 없는 611/711개(85.9%)는 속성 결손이며 현실 누락률이 아니다.

다른 작업 사본에서도 대형 원본 없이 같은 집계를 재현했고, 사용 정책·후보 ID·수동 검토 상태·완료 체크의 일치를 확인했다. [D04 검증 기록](../data/reports/d04_verification.json). 현재 M1의 기존 환경에서 확인했으며 게임·M4 실행 시험은 아니다.

- 상세 랜드마크·실제 지형과 전체 통합 보행 검수는 미구현이다. 대한문 밖↔경내 입구의 제한된 보행 연결은 W01에서 구현했다. P01 크기·P02 이동/복귀·P03 3인칭 카메라는 독립 시험장에 있고 P04는 실제 도시 정적 충돌을 별도 장면에 연결했다. W01에서 대한문 연결, W02에서 원문 경내 순환·앞마당을 검증했다. W03에서 시청/광장·돌담길의 자동 왕복과 장면 경계를 검증했다. 전체W0 통합 검수는 W04다.

.venv-data/bin/python tools/prepare_osm.py audit data/raw/deoksugung_cityhall-v2.osm.pbf

다른 기기에서 데이터 준비 환경이 필요할 때(현재 기기에는 완료), Python 3.14를 준비한 뒤 실행한다. 읽기 순서와 기기별 설정은 [CROSS_MAC](CROSS_MAC.md)을 따른다.

```sh
bash tools/setup_mac.sh
```

지역 추출물을 새로 생성할 때만 실행한다. 기존 파일은 자동 덮어쓰기하지 않는다. 원본 갱신은 새 스냅샷/출력 이름과 manifest로 관리해야 한다. 아래 명령의 새 출력 이름은 실제 새 스냅샷에 맞게 지정한다.

```sh
.venv-data/bin/python tools/prepare_osm.py extract data/raw/geofabrik/south-korea-261009.osm.pbf --output data/raw/deoksugung_cityhall-new.osm.pbf
.venv-data/bin/python tools/review_osm_extract.py
```

`data/processed/osm_preview.geojson`은 WGS84 검사 결과이지 게임용 미터 좌표 자산이 아니다. `tools/check_coordinates.py`로 `coordinate_reference.json`을 생성하며 같은 기준은 공유 보고서에도 담겨 있다. 재현 시 감사 보고서의 미리보기 해시와 설정 해시도 대조한다. 지역 지도 v2·비교용 v1·명시한 Overture 소구역·DSM 참고 사본은 Git 공유 대상이다. 국가 원본·전체 DSM·컬럼 정의서/참고 HTML·가상환경·가공물은 제외하며 보고서/설정/도구/수동 보정은 추적한다. 전용 저장소는 [codemillss/Sim2Seoul](https://github.com/codemillss/Sim2Seoul), 다른 Mac 준비는 [CROSS_MAC.md](CROSS_MAC.md)를 따른다. 현재 다음 구현 작업은 위 W04다. P04 정적 충돌 계획은 기존 E03 준비 후 `tools/prepare_collision.py`로 생성한다. `tools/prepare_features.py`→`tools/check_geometry.py`→`tools/prepare_heights.py`→`tools/check_heights.py`→`tools/prepare_movement.py`→`tools/check_movement.py`로 도형·높이·지면·이동 후보를 재생성한다. G03/G04 분류는 [height_review](../data/reports/height_review.md)와 [movement_review](../data/reports/movement_review.md)를 따른다. 이전 공유 검사도 [G02](../data/reports/geometry_check-g02.json)·[G03 도형](../data/reports/geometry_check-g03.json)·[G03 높이](../data/reports/height_check-g03.json) 스냅샷으로 보존했다. E04는 `prepare_scale_view.py`로 고정 기준을 재생성하며 `run_scale_view.sh`로 다시 연다.

## 개발 환경 기록

- 현재 기기: M1 Pro, CPU 8코어/GPU 14코어, RAM 16GB, macOS 27.0. 직접 확인한 사양.
- 추가 기기: 사용자 제공 M4 Pro, SSD 1TB. RAM·OS는 아직 확인하지 않음.
- 디스크 여유는 E01 시작 때 약 12.02GiB였으며 현재 값으로 가정하지 않는다. 큰 다운로드/템플릿 준비 전에 재확인.
- Godot 4.7.2 Standard 설치 완료, Forward+/Metal. E03 actual map GPU 표시 확인. 내보내기 템플릿은 R03 전 준비.

## 이번 검증의 한계

추출기는 교차 웨이와 선택된 관계의 뒤쪽 참조를 보완한다. D02는 국가 원본의 관련 복합 면을 조사 영역과 교차/포함 비교하고 부모 관계를 반복 추적해 누락을 보완했다. 국가 원본에서 조립되지 않은 37개 복합 면은 위치를 확정하지 못하며 현재 지역 구성원과의 연결도 발견되지 않았다. 국경/행정/긴 노선 관계는 목적에 따라 제외했다. 세부 한계는 D02 결과와 추출 manifest에 남겼다.

참조 0건 누락과 기하 유효성 통과는 데이터 구조 검사다. 현재 실제 서울의 위치·높이·접근 가능성에 대한 완전성을 증명하지 않는다. 현장 수준 정확도와 게임 검증을 구분해 보고한다.
