# N01 보행자·차량 경로와 교차 규칙

2026-10-15 · 계약 `N01-routes-v1` · **경로/규칙 계획 완료, 실제 controller는 N02/N03에서 구현·검증**

수동 원천은 [urban_routes.json](../data/manual/urban_routes.json)이다. `tools/prepare_routes.py`가 기존 G04/W03 자료를 검증하고 로컬 `data/processed/npc_routes.json`·`vehicle_routes.json`을 만든다. 가공 파일은 Git에서 제외하고 [검증 스냅샷](../data/reports/n01/plans/)·생성기·작은 원천과 작업 맥락을 공유한다. 현재 game/모델·플레이어·충돌·경계/지원면은 변경하지 않는다.

## 경로 선택과 모드별 영역

| 보행자 경로 | 장소 | 편도 / 주기 거리 | 원천 연결 |
|---|---|---|---|
| palace_court | 중화전 열린 앞마당 | 47.011114m / 왕복 94.022228m | 기존 W03 `court_approach` 정점 0–11 |
| plaza_front | 시청·서울광장 전면 보행면 | 73.713895m / 왕복 147.427790m | 기존 W03 `city_plaza` 정점 97–98 |

NPC 중심선은 기존 W03 이동 영역 안에 두고, 반경0.30m+여유0.05m의 전체 보행 띠가 기존 지원면 안에 있어야 한다. 원문에서 이미 보정된 W03 실행 정점을 그대로 선택했으며 새 지름길이나 건물 진입은 없다. 속도1.2m/s, 끝에서 정지 후 제자리 회전/왕복을 기본안으로 둔다. 사람/다른 NPC를 밀지 않고 멈추며, 방향을 바꾸려면 뒤쪽 capsule 공간을 다시 확인한다. 자동 복귀나 순간이동으로 막힘을 감추지 않는다.

| 차량 경로 | 원문 way | 원문 시작→끝 누적거리 | 게임 중심선 길이 | 북측 횡단 정지 여유 시작 s |
|---|---|---|---|---|
| sejong_south | `osm:way:1084408283:highway_line` | 5→195m | 189.962601m | 13.432108m |
| sejong_north | `osm:way:378453707:highway_line` | 5→260m | 255.073117m | 200.180717m |

두 원문은 `oneway=yes`, `lanes=8`, `source_forward`다. 이는 **원문 태그의 방향/차로 수 근거**이며 실제 현장 차로를 측량했다는 뜻이 아니다. 차로별 위치/용도·폭은 자료에 없다. 게임은 진행방향 왼쪽부터0기반4번, 폭3.2m 가정으로 오른쪽1.6m 오프셋을 사용한다. x=동/z=남에서 오른쪽은 `(-dz,+dx)`이며 Shapely 양수 오프셋에 대응한다. 반대쪽 차도로 U턴하거나 역주행 왕복하지 않는다.

차량4.2×1.8×1.5m와 모든 방향의 차체를 포함하는 반경2.6m 연속 띠로 영역/장애물을 검사했다. 차량 영역은 **선택한 G04 도로 후보∩기존 배경 범위**로 한정한다. G04의 `candidate_geometry`는 R1/R2/R3 보행 검토용이어서 보편적인 차량 경계로 사용하지 않는다. 사유지/경내·NPC 띠/반대 차량 띠를 제외하고, 기존 W03 보행 영역과의 접촉은 지정 횡단부만 허용한다. bbox나25.6m 추정 도로 버퍼가 자유 보행/실제 차선·통행 권한을 만들지는 않는다. 두 도로 추정 버퍼가 겹칠 수 있으나 선택한 차체 띠2개는 겹치지 않는다.

남행의 처음5→235m 후보는 차체 띠가 횡단부 밖 보행 영역12.347679㎡를 침범해5→195m로 줄였다. 폭/차체 여유·기존 플레이 경계를 완화하지 않았다. [후보와 수정 근거](../data/reports/n01/development/candidate_review.json).

## 횡단부 점유와 우선순위

W03의 `sejong_marked`, `side_street`, `west_junction` 원천/공유 노드3곳을 보존했다. 현재 차량2경로가 만나는 곳은 `sejong_marked`이며 나머지2곳에는 활성 차량 경로를 두지 않았다. 새 신호 체계나 실제 신호 주기/법규를 복원하지 않는다.

1. 사람 점유 구역은 기존 횡단 도형에0.35m를 더한 영역이다. 차량 중심의 충돌 구역은 여기서 차체 반경2.6m를 추가한 영역이며, 전체 차체가 빠져나가야 점유를 해제한다.
2. 정보가 없거나0.1초보다 오래됐으면 정지한다. 플레이어·보행자가 우선이며 차량이 이미 구역 안에 있어도 사람이 들어오면 정지 대응을 우선한다. 점유 시간 초과를 이유로 밀고 지나가거나 사람/차량을 초기화하지 않는다.
3. 사람이 없어진 상태가1초 유지되고 차량 점유가 없을 때 대기열 선두1대만 진입을 예약한다. 차량끼리는 FIFO, 구역당1대다. 한쪽 진행방향에 영구 우선권을 주지 않는다.
4. 속도5m/s, 반응0.5초·제동3m/s²·여유1m라는 **계획 가정**으로 `5×0.5 + 5²/(2×3) + 1 = 7.666667m`를 확보했다. JSON `stop_s_m`는 확장 충돌 구역 진입보다 이 거리만큼 앞이다. 도로의 실제 정지선이나 실제 엔진 제동 거리로 설명하지 않는다.
5. 지정 횡단부 외에서도 진행 방향 전체 차체 띠에 사람/차량이 있으면 정지한다. N03에서 연속 감지·제동·진입 후 사람 출현·점유 해제·정지/재개를 실제 물리로 검증한다.

## 반복·끝점·막힘

보행자 주기는 같은 실제 선을 왕복한다. 차량은 편도 stream으로 두고 끝의7.666667m 전부터 정지 준비를 시작한다. 끝점을 서로 잇는 공간 경로는 `null`이며 새 도로·역주행·폐회로를 만들지 않았다.

차량 재진입은 끝에서 멈춘 뒤 **진입/퇴장 차체 전체 영역이 실제 카메라 frustum 밖**, 두 끝점 주변 사람과30m 이상 거리, 진입 차체 영역의 동적 점유0을 모두 다시 확인할 때만 허용한다. 조건이 불확실하거나 화면에 보이면 계속 대기한다. 실제 카메라·동적 점유를 아직 구현하지 않았으므로 N01이 반복 운행 성공을 보장하지 않는다. N03은 같은 프레임의 이 조건과 겹침/눈앞 소멸0, N04는 실제 최소2주기를 확인한다.

차도 지면은 기존 y=0 가정을 유지하지만 **차량용 실제 지원면/접촉은 미검증**이다. N01은 지원면을 추가하지 않는다. N03에서 현재 장면의 지지를 먼저 확인하고 필요한 경우 원천 도로 범위의 제한 지원면을 별도 기록·검증한다. 플레이어 경계를 넓히는 이유로 사용하지 않는다.

## 초기 개체 수와 다음 검증

초기 제안은 경로마다1개체, NPC2/차량2다. NPC 초기 위상0.5는 편도 누적거리의 절반/원래 정점 순서 진행이며 차량은 생성 경로의 시작점0이다. 아직 개체를 생성하지 않았고 성능 결과가 아니다. 기존12/4·24/8 부하 프로필은 후속 성능 검증 제안으로 유지한다.

N02는 이2개 NPC 경로부터 사람 접촉·정지/재개·왕복/회전과 영구 고착0을 관측한다. N03은 위 차량 지지/정지거리·점유/FIFO·화면 밖 반복을 구현한다. N04의10분 이상 관찰/최소2주기는 N01 기하 검사로 대체하지 않는다. 좌표/원천 해시·manifest 검사를 유지하고 런타임은 Git 제외 작은 `res://` 사본을 읽게 구성한다.
